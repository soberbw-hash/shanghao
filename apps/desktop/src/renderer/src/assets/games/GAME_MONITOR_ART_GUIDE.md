# 上号游戏显示器作图规范

这份规范用于以后给新的游戏添加显示器画面。房间里的显示器最终只有约 `110 × 70 CSS px`，所以画面目标不是做完整海报，而是让用户一眼认出这款游戏。优先使用官网、官方媒体包或开发商发布的 Steam 商店实机截图；不要先凭游戏类型生成一张可能跑偏的概念图。

## 固定输出

- 横向 `16:10`，交付 `768 × 480 WebP`。
- 建议 WebP quality `82`，单张尽量小于 `100 KB`。
- 优先选择没有大段文字、Logo、水印和复杂 HUD 的官方实机画面。
- 保持静态图片；整张场景图不做循环缩放、位移、闪烁或扫描动画。
- 在 `SOURCES.md` 保存原始网页和图片直链；正式发版前复核对应素材使用条款。

## 官方素材查找提示词

```text
为“[游戏名]”寻找可用于上号微型游戏显示器的官方实机画面。
只接受游戏官网、官方 press kit、开发商或发行商发布的 Steam 商店素材。
优先横向截图，必须一眼能认出这款游戏；主体位于中间，缩到 110×70 像素仍清楚。
排除纯 Logo、竖版海报、文字很多、HUD 很密、主体贴边、过暗或过曝的图片。
返回原始页面、图片直链、发布者，以及为什么适合 16:10 中心裁切。
```

## 小屏二改提示词

```text
以附带的官方游戏截图为唯一视觉底图，制作上号微型显示器版本。
不要重画角色、地图、建筑、武器或游戏美术风格，也不要添加新物体、文字、Logo、边框或 HUD。
只允许为 110×70 像素可读性做处理：中心或焦点裁切到 16:10、适度提亮暗部、控制高光、
轻微调整饱和度和对比度、降噪、轻锐化，最后输出 768×480 WebP。
必须保留原图最能代表该游戏的主体；缩略后不能变成色块或黑块。
```

## 已验证素材方向

- 星露谷物语：官方农场实机图，农舍、作物和玩家角色共同入画；中心裁切后仍保留完整农场特征。
- 英雄联盟：Riot 官方教学页的召唤师峡谷野区场景；大型野怪、英雄和峡谷地面在小屏中轮廓清楚。
- 三角洲行动：官方城市战场实机图；枪械、城市和直升机形成清晰三层焦点，比泛化士兵海报更像真实游玩画面。

## 两轮审核

第一轮审核原图和 `110 × 70` 缩略图：

- 焦点、人物或目标在缩略图中仍可辨认。
- 素材来自官方页面，来源链接已记录；没有额外添加文字、Logo 或水印。
- 暗部没有糊成一块，主色不混浊。
- 构图边缘留有裁切余量。

第二轮放进真实 Electron 房间后审核：

- 在一号房和五个座位的显示器尺寸下都不显挤、不显黑。
- 不遮挡人物、座位号、状态卡片或活动图标。
- `object-fit: cover` 裁切后焦点仍在，浅色房间里对比足够。
- 整图保持静态，开启减少动画时没有额外运动；房间帧率无明显回退。

两轮都没有明显问题才提交。如果第二轮失败，优先改构图、裁切位置或亮度，不要往显示器里继续堆元素。

## 新游戏接入清单

1. 在共享 `GameDetectionSnapshot` 联合类型中加入固定中文名。
2. 在 `GAME_RULES` 添加明确的可执行进程名，避免模糊匹配。
3. 把优化后的 WebP 放入本目录，并在 `SOURCES.md` 记录官方页面、图片直链和发布者。
4. 在 `GameMonitorContent.tsx` 注册画面；需要满屏氛围图时使用 `layout: "scene"`，并选择 `cozy`、`moba` 或 `tactical` 明暗基调。
5. 更新 `docs/supported-activities.md` 和 `tests/game-detection.test.ts`。
6. 按上面的两轮审核流程留存截图与结论。
