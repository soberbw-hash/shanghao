# 上号 ShangHao

**给固定朋友长期挂语音、开黑和聊天的 Windows 桌面语音房。**

进房以后，谁在玩游戏、听歌、接电话，谁暂时离开，都能在房间里看到。声音、聊天、一起看的画面，还有昨晚的录音，待在同一个地方。

## 朋友一直在线，房间应该看得懂

我们自己长时间挂语音时，常碰到的麻烦很小，却每天都会来：朋友半小时不说话，不知道是去拿水了，还是麦克风坏了；有人声音太轻，有人一开口就很响；昨晚聊过的东西，第二天只记得“好像挺好笑的”。

上号围绕五个人以内的固定房间做这些细节。它保留一号房和二号房，各自有成员、聊天与记录。打开房间，先看见人，再看见状态。

### 人物会告诉你，朋友现在在做什么

成员入座、说话、离开和回来，会反映在人物与场景里。支持的游戏会出现在工位上；音乐状态可显示当前歌曲；电话模式和屏幕分享也有自己的反馈。有人没回话时，看一眼房间通常比再喊一遍名字更快。

![房间人物、座位与成员状态局部](./docs/readme/room-presence.webp)

长时间离开电脑也会被照顾到：连续 30 分钟无操作，上号会自动进入离开位置并静音麦克风；重新操作后回到原座位，依据当时的扬声器状态决定是否恢复麦克风。手动离开不会被自动返回覆盖。

窗外的天气与昼夜、房间里的时钟和可点开的日历，都是场景本身的一部分。

![房间窗外、日历和时钟局部](./docs/readme/room-weather.webp)

### 五个人说话，先把每个人的声音照顾好

键盘声、底噪、扬声器回声和麦克风音量差异，在一整晚的语音里很难忽略。麦克风面板提供 DeepFilterNet3 降噪、回声消除、人声增强、自动增益与三秒麦克风体检；输入和输出设备可以分别选择，每位朋友的接收音量也能单独调。

可选的响度匹配会平滑调整各路接收声音，减少反复追着系统音量条调的次数。它以约 −16 LUFS 为目标，仍保留个人音量控制；最终听感取决于设备和网络。

![麦克风处理面板局部](./docs/readme/audio-panel.webp)

电脑临时没有麦克风时，可以打开“使用手机麦克风”：手机浏览器扫码、授权麦克风，不用另装 App。Android 另有 USB 连接方式，需要数据线、USB 调试和设备授权。配对服务需要可用的 HTTPS；不同手机与网络仍需实机确认。

### 房间里的梗，留在房间里

“我的快捷消息”把五个语音／音效槽位和三个音乐槽位放在一起。音频库支持试听、搜索、筛选和拖拽绑定，也能设置快捷键、播放开关与音量。朋友之间常说的口头禅，想放就放。

![我的快捷消息：语音与音效槽位、音乐槽位及音量控制](./docs/readme/quick-message-slots.webp)

喊半天没人回，可以**敲一敲**，给对方一个显眼的本地提醒。要拉朋友进来，房间里的**邀请**入口会复制加入链接。

聊天也做了几件顺手的小事：链接成为可点击卡片，在系统浏览器打开；能获取网页图片时显示缩略图；图片有预览。消息、图片和链接可直接拖进房间收藏，右键即可复制。发送过程有确认、重试与去重，两间房的聊天彼此隔离。

一起看网页、让朋友帮忙看操作或分享游戏，可以选择屏幕或窗口共享，并可选分享系统音频。需要给微信发语音时，电话模式通过快捷键临时处理电脑音频与上号麦克风，结束后恢复；部分独占音频设备可能绕过软件静音，应用内会提示。

### 昨晚那句话，第二天还能找回来

房间可按设置自动录音，录音保存在本机。回放时可以标记精彩时刻、收藏、查看转录文字；长录音还可进一步整理。房间记录按天保存成员、活跃时长、游戏、消息数和屏幕分享情况。整理出的摘要只有用户明确发布后才会进入共享的每日记录。

本地转录模型按高精度和高速度分组，可独立安装。不同模型在说话人、时间信息和运行条件上各有差异；整理与问答结果也需要自己核对。若房间问答使用云端服务，应留意所连接服务器的配置与数据边界。

![AI 功能中的模型分类、推荐标记与安装状态](./docs/readme/ai-models.webp)

## 里面是怎么运转的

房间看起来简单，底下同时处理成员状态、实时媒体、Windows 设备、屏幕采集、录音文件和模型进程。我们把它们分开管理，因为“连接成功”与“真的听见朋友说话”是两件事。

### 五人语音：连接按成员建立，故障按成员恢复

五人全互联对应 **10 条成员间连接、20 条定向媒体路径**。这是拓扑规模，不是对任何网络条件下并发听感的承诺。成员通过 WSS 信令交换协商信息，语音优先使用 WebRTC/Opus；直连遇到困难时可借助 TURN，必要时启用定向 Relay 音频兜底。

![信令、WebRTC Mesh、Relay 与远端混音的运行链路](./docs/assets/architecture-runtime-flow.svg)

每位远端成员有独立的协商队列与媒体状态。后加入者的 Offer、Answer、ICE 按成员处理；提前到达的 ICE 先缓存。只有统计确认收到该成员的入站 RTP，才把这一路标记为可用。若这一路停滞，就针对这位成员恢复或回退，不让正常的几路跟着重连。

![WebRTC 与 Relay 按成员恢复的状态图](./docs/assets/architecture-media-recovery.svg)

### 桌面能力：接口窄，职责清楚

React 渲染层负责房间、交互与媒体编排；预加载层只暴露显式、类型化的桌面能力。Electron 主进程处理窗口、系统集成与屏幕源；`PlatformService` 收拢平台差异，`ScreenCaptureService` 统一源枚举与选择，`ScreenShareManager` 持有分享 Track。Rust Core 承担 Windows 活动查询、稳定文件身份和 AI 子进程监督等适合原生层的任务。WebRTC、Opus、AEC、DeepFilterNet3 与模型算法继续沿用各自成熟的实现。

![React、类型化桌面接口、Electron 与 Rust Core 的职责边界](./docs/assets/architecture-core-platform.svg)

| 设计选择                  | 解决的实际问题                                         |
| ------------------------- | ------------------------------------------------------ |
| 信令与媒体分开            | 服务器管理成员与协商，朋友之间的媒体优先直接传输。     |
| 按成员恢复 WebRTC / Relay | 某一位朋友的链路出问题，不必让整个房间一起断音。       |
| 聊天 ACK、重试与去重      | 短暂断线后减少漏消息和重复消息。                       |
| 录音、模型主要留在本机    | 日常资料不随每次房间交互上传；共享摘要由用户主动发布。 |
| 视觉任务随页面可见性暂停  | 天气、角色等动画停下时，语音、录音与信令继续工作。     |
| 更新后台下载，手动安装    | 下载完成后，由用户决定何时安装并重启。                 |

想看更细的实现和边界，可以接着读[架构说明](./docs/architecture.md)、[动效规范](./docs/motion-guidelines.md)、[本地多人验收说明](./docs/local-multiplayer-acceptance.md)。这些图展示设计与实现路径，真实五人听感仍以设备实测为准。

## 下载，叫上朋友

当前仓库版本为 **3.2.1**，正式支持 **Windows 10 / 11 x64**。[下载 v3.2.1 安装包](https://github.com/soberbw-hash/shanghao/releases/download/v3.2.1/ShangHao-3.2.1-Setup-x64.exe)，或从 [Releases 最新页](https://github.com/soberbw-hash/shanghao/releases/latest)选择版本；同页提供 SHA-256 校验文件。[v3.2.1 更新公告](./docs/release-notes/v3.2.1.md)有本次改动。

账号可通过 CloudBase 手机号验证注册；安装后登录账号，进入一号房或二号房，邀请朋友加入同一服务。服务器承担成员、信令、聊天与必要的共享状态；录音、模型等资料主要保存在本机。自行部署可参照 [Relay](./docs/deploy-relay-server.md)、[TURN](./docs/deploy-turn.md) 与[网络修复](./docs/network-repair.md)文档。

**实机验收边界：** 自动化回归覆盖五人路径，但不能代替五副耳机的现场听感。已安装旧版客户端完成“发现更新 → 下载 → 用户点击安装重启”，以及手机麦克风在朋友设备上实际听见，仍需分别实测。

## 给想看代码的人

| 目录                              | 职责                                        |
| --------------------------------- | ------------------------------------------- |
| `apps/desktop`                    | Electron 主进程、预加载层、React 房间与设置 |
| `packages/signaling`              | WebSocket 信令、成员和房间状态              |
| `packages/webrtc`                 | Peer 生命周期、音频约束与恢复辅助           |
| `packages/recording`              | 录音状态、编码与导出抽象                    |
| `packages/shared` / `packages/ui` | 共享契约与 UI 基础组件                      |
| `native`                          | 聚焦 Windows 能力与受控后台任务的 Rust Core |

技术栈为 Electron、React、TypeScript、Vite、Zustand、Node.js/ws、WebRTC 与 Rust。开发规则见 [AGENTS.md](./AGENTS.md)；Windows 是正式支持平台，macOS 目前保留能力降级边界。

```powershell
corepack pnpm install
corepack pnpm dev
corepack pnpm typecheck
corepack pnpm --dir apps/desktop test:smoke
```

修改语音、录音或屏幕分享之前，请先看相应架构说明与现有回归。公开仓库里的名称、图标、角色，以及第三方音频和模型资源各有使用边界；音频素材不能一概视为可自由再分发。
