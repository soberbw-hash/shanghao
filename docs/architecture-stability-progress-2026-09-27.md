## 录音 Runtime 的失败与并发边界

流式写入报错后，已停止的编码器会释放自身引用，允许下一段录音正常启动；`RecordingService` 将错误状态明确标为失败。失败会话通过显式 `sealSession` 能力关闭主进程文件流并保留临时音频与恢复元数据，不调用会删除文件的 `abortSession`。会话创建时元数据写入失败也会封存句柄，保存失败继续返回原始错误。导出接口抛异常及主动丢弃失败不再让界面停在“正在保存”或“正在停止”。

一次停止请求只执行一次编码与导出；停止、保存和说话人片段收尾完成前，Renderer 不会新建混音资源或丢弃当前录音。旧收尾只释放自己捕获的混音实例，不再无条件释放可能已更新的全局引用。用户请求丢弃但主进程删除失败时会显示失败，避免误称“录音未保存”。模拟写入故障、导出异常、重复停止和并发启动/丢弃的定向测试通过；真实长录音、磁盘满和设备中断仍待实机验证。

非流式导出的临时文件使用 UUID 和独占创建；最终录音名称也先原子占用，同名并发导出会顺延编号，不能覆盖已有录音。编码或复制失败时清除未完成的输出占位，保留临时输入；输出已经完成但登记失败时保留完整文件供恢复。文件名并发测试使用独立系统临时目录，没有触碰用户录音。

## 设置界面回归检查

屏幕分享启动后如果发布 Track 或启用内容保护失败，现在只回滚当前操作拥有的发布会话并停止其采集 Track；已被后续操作取代的旧启动不得清理新分享。停止操作等待进行中的发布结算，下一次分享等待旧停止完成；自动恢复及销毁时也会按发布归属收尾，避免旧操作把画面重新挂到 Peer。停止分享时，即使某个 Peer 拒绝移除屏幕 Track，也会继续尝试其余 Peer、恢复主麦克风、停止本地 Track 并广播结束。7 个定向屏幕分享生命周期测试、708/708 smoke、TypeScript、lint、普通构建与五人媒体自动化通过；多 Peer 的真实分享、屏幕音频混音与中途断线仍待实机验证。

离开房间时若屏幕音频恢复主麦克风失败，仍会释放屏幕混音器、采集 Track、信令连接及其余房间资源；独立失败注入测试通过。正常音频发送和恢复路径没有改动，真实设备的系统音频分享与故障恢复仍待验证。

使用独立临时 `userData` 和本地视觉捕获信令服务打开 Electron 设置页，没有触碰真实账号、录音或模型目录。截图确认：登录卡片右上角显示声音检测；快捷消息页把语音 8 槽、音乐 5 槽、播放开关和音量放在同一页，音频项保持紧凑；AI 页无模型搜索框；房间记录页无搜索框；通用页 Windows 外观实验功能直接展开。隔离环境没有已安装模型，故模型“删除”菜单的实际悬浮/离开交互仍未从界面验证，只有代码中的离开与失焦关闭逻辑。

诊断页及“复制易读摘要”共用真实 Track、处理链、输出路由、混音器和 Peer 的状态投影；没有进入房间或没有远端音频时显示“未检测”，屏幕分享诊断对象存在但画面尚未开始时也不报“正常”。降级与故障有不同提示。它不会把发现设备、取得运行指标或连接建立直接表述为朋友已经听到声音。

健康总览现从逐项状态保守汇总整体结果：有故障优先提示故障，有降级则提示需要处理，任何关键项未检测时不会显示整体正常。单次取得本机 CPU、内存等指标只作为信息展示，不计入“正常”项。汇总规则与诊断文案回归测试通过；远端实际听感仍需双方确认。

该阶段的全量 smoke 为 758/758，workspace `typecheck`、lint 与普通 `build` 通过；Rust 2/2 测试通过。五人信令音频自动化覆盖 20 条定向路径、后加入和重连，Electron 五人媒体自动化覆盖 20 条可解码音频路径及 A/E 恢复；媒体测试使用独立临时 Electron 用户目录。另在隔离目录生成了 NSIS 候选包，完成静态资源和体积校验，没有安装或发布。这些自动化仍不能证明真实朋友听到手机麦克风，也不能代替旧版客户端更新验收。

远端自动响度学习现在同时参考成员的远端说话状态和本机测得的 RMS、峰值；明确静音或在已观察到说话信号后明确未说话时保留既有增益，不从键盘、碰撞等能量样本继续学习。单个分析帧峰值远高于 RMS 的瞬态也不计为稳定语音。对尚未观察到说话信号的非静音成员保持原有能量门限回退，避免旧客户端无状态上报时永远无法学习；声音播放、手动音量和安全限幅路径不变。定向测试覆盖静音、瞬态、真实说话及状态缺失；真实朋友之间的听感与旧客户端状态兼容性仍待双端验证。

远端成员的说话状态、延迟等变化现在仍送入各自状态处理，但不会仅因成员数组变化就重复调用混音器的完整流同步。远端流对象、音轨 ID、音轨可播放状态、成员音量或成员列表变化时仍同步；定向测试覆盖音轨、可播放状态与音量变化。此优化减少房间状态频繁上报时的混音器工作，不代表已测得真实设备上的帧率或 CPU 降幅。

独立的 `RuntimePressureController` 现持有压力观测、8 秒恢复滞后和 30 秒失联有效期，模型管理器只把结果应用到调度器。持续上报会顺延有效期；上报中断后，瞬时 Peer 恢复、网络延迟/丢包和 Renderer 内存压力不会永久暂停 AI 与下载。房间连接、录音和屏幕分享状态仍保守保留，防止失去上报时误放开实时路径。失败注入定向测试验证了瞬时压力过期、录音与房间保护继续生效；真实睡眠恢复和长期运行待实机观察。

“安全重置”现在先取消成员音量的待执行延迟保存；主进程重置成功后，清空本次运行的成员音量映射，并把当前房间每位远端成员的本地播放增益及 Relay 回退增益恢复为 100%。成员音量持久化模块改为由设置层注入读写接口，避免它反向导入整个 Zustand Store。独立测试验证延迟保存取消、映射清除以及本地成员/空座位不被误改；真实通话中的重置听感仍待实机检查。

房间退出现在复用同一个清理 Promise；若两个调用几乎同时退出，后一个会等待前一个真正完成信令关闭与资源清理，不会提前报告已退出。延迟关闭的定向测试验证只执行一次清理；真实快速退房重进仍待设备端观察。

同一个信令桥重连时会切换事件队列代际；旧连接仍在排队的事件和迟到失败回调不会进入新队列，关闭时也会使旧队列失效。模拟旧事件阻塞、新连接消息先到和旧任务随后失败的定向测试通过。已经开始执行的旧回调无法由队列取消，仍依赖房间 Session 和 Peer 归属检查；真实断网重连仍待设备端验证。

若新连接尝试覆盖尚未结束的旧尝试，旧连接 Promise 现明确以“已被取代”结束；退房或连接关闭也会结束各自尚未完成的尝试。超时与迟到的 `connect` 失败只允许处理自己创建的待连接对象，不再拒绝下一次尝试。模拟重叠连接与迟到失败的定向测试通过；真实频繁断线和快速重进仍待设备端观察。

主进程创建信令 WebSocket 前现在会在日志和账号令牌两个异步边界后核对连接代际；旧请求迟到的令牌不能覆盖新连接。Renderer 每次重连使用新的信令会话 ID，迟到的旧关闭请求会被主进程识别为旧会话并忽略。本地受控 WebSocket 测试覆盖这两种竞态；真实断网与账号刷新同时发生的恢复仍待实机观察。

## 仍需分阶段完成

本地补充（2026-09-28）：加入房间时先完成设置与服务器地址校验，再推进 Session 代际；无效请求不再使仍在使用的房间资源失去归属。AI 模型下载等待队列补上入队时的取消竞态检查，并在取消时移除监听器，避免一个已取消的请求占住下载槽位。最近 10 分钟的房间、音频 Relay 和 AI 计算事件现按时间合并为最多 512 条的诊断时间线；事件和原因均使用固定白名单，不复制聊天或转录正文。定向测试及 TypeScript 检查通过，真实跨设备故障链路仍未验证。

聊天历史与房间日报读取遇到损坏或未知版本时，现在拒绝后续写入，保留原文件，不再把异常读取当成空数据覆盖；只有文件确实不存在才初始化空缓存。缓存状态在原子重命名成功后提交。聊天历史的 24 MiB 裁剪改为逐条计算序列化大小，避免反复对整个数组编码。上述回归测试均在独立系统临时目录运行，未读取或清理真实用户数据。

语音记忆的索引、摘要和单条记录也区分缺失与损坏：损坏文件不再被当作空记录；保存同一录音前核对现存文件可读，防止把旧转录覆盖。存储层仍通过原有原子写入路径提交，49 项语音记忆定向测试通过。损坏数据需要单独恢复，不会自动删除或重建用户文件。

设置主文件与备份都无法读取时，仅在内存中提供默认视图并阻止普通保存，不覆盖任一旧文件；用户显式重置仍可重新初始化。账号会话或“记住登录”暂时无法解密时，不再自动删除加密文件。旧版语音记忆记录的最小结构继续允许读取；相关设置、账号、旧版存储夹具 22 项定向测试通过。真实用户目录没有作为测试夹具。

设置写入现要求旧设置备份成功后才覆盖主文件；备份失败时原主文件保持不变，内存视图回退到此前值。显式重置在持久化失败时同样回退内存状态，旧头像清理延至持久化成功之后。独立临时目录的备份失败注入与回退测试通过。

账号恢复和定时刷新遇到服务器不可达等错误时，现只撤销当前内存会话，保留加密会话文件；显式退出、访客切换或用户选择不记住登录仍按原有意图清除。服务器不可达的失败注入测试确认旧会话字节不会被删除。保留凭据不等于已经恢复登录。

补充收口：CloudBase 启动时会先以系统加密存储中的凭据调用 SDK 的恢复接口，再读取个人资料，避免只凭 SDK 内存状态判断旧会话。账号服务器 5xx、网络不可达与 Supabase 可重试的刷新错误显示为暂时不可用；服务端明确拒绝的失效令牌仍显示退出。两类错误均不会自行删除加密会话文件。记住登录的会话遇暂时故障后按 10、30、60 秒最多重试三次；用户主动登录或退出会等待正在进行的恢复并取消后续重试。模拟服务端的自动恢复与退出取消测试通过。网络长时间中断后重试会停止，不会无限后台请求；真实 CloudBase 账号重连仍待实机验证。

加密会话和记住登录的文件读取现在只把文件确实不存在视为空；权限或路径等读取错误会向上报告，避免掩盖存储故障。独立临时目录的失败注入测试通过，未改动真实账号文件。

语音记忆索引文件确实缺失时，启动会从可读的原始记录重建搜索索引；摘要缺失时同样重建。遇到损坏记录则中止恢复，不覆盖损坏文件；旧版仅有录音路径和转录的最小记录在内存中补足必需字段，磁盘原文保持不变，直到后续显式保存。遍历大量记录时磁盘并发读数限制为 8。独立临时目录中的缺失索引、旧记录和损坏记录测试通过；真实大规模语音记忆目录的启动耗时尚未量测。

补充校验了搜索索引条目、摘要条目及转录词级时间戳等运行时必需字段。保存新语音记忆前先验证输入记录并计算摘要、索引，异常输入不会先改写原记录。旧索引中的匿名转录条目会在内存中补上显示标题；N-1 夹具中仅含录音 ID 和标题的旧摘要也从对应原始记录在内存中补全，不改写原文件。索引文件存在但为空时，若原始记录仍有内容，搜索索引会在内存中恢复，也不改写旧索引。缺少对应原始记录的旧摘要仍报错并保留磁盘内容。语音记忆定向测试与 N-1 存储夹具通过；真实用户历史目录的所有形态仍需只读核验。

语音记忆的记录、摘要与搜索索引分文件写入，现于写入前创建不含录音身份的提交标记；重启时若标记仍在，会先完整读取源记录，再恢复派生摘要和索引，成功后才移除标记。即使派生索引损坏，有有效提交标记时仍可从完整源记录恢复；没有标记的损坏索引继续保留并报错。写入失败的当前进程会拒绝后续记录保存、删除以及派生索引查询，避免把过期数据当作最新结果。独立临时目录模拟了写入和删除中断，并注入索引写入失败；恢复后的搜索与摘要正确，语音记忆定向测试 56/56。未对真实用户目录进行恢复试验。

诊断包中按时间合并的音频事件现保留经白名单验证的 WebRTC/Relay 起止路径、音频流代际、队列时长和丢弃片段数。时长与计数设有上限，未知字段和正文继续剔除；三项时间线测试验证顺序、字段过滤及 512 条容量。它可帮助定位 Relay 切换，但真实远端音频故障仍需要设备日志和双方听感一起确认。

合并后的 AI 事件还保留固定任务类别和主动/自动标记；非法类别、非布尔标记以及自由文本不会进入导出的时间线。四项定向测试通过。自定义 AI 服务的加密配置改为先写独占临时文件再原子替换；损坏或不可读的旧配置会报错并保留原字节，不再被当成“未配置”后覆盖。模型目录首次迁移同样原子写入合并状态和完成标记；损坏的现有状态会中止迁移并保留原文件，残缺的完成标记会触发安全重试。旧模型或 Runtime 复制失败时会记录错误并拒绝写入完成标记，下次启动仍可重试。上述数据保护测试只使用隔离临时目录，没有操作真实凭据或模型。

模型和可选 Runtime 的下载流现在按清单大小限制写盘；异常响应无法把续传文件持续撑大，非法大小也不会启动下载。定向测试模拟了超量响应，真实模型目录只做了文件数和体积的只读统计，详情见包体积审计。模型内容与现存续传文件均未删除。

转录预处理的 FFmpeg 媒体探测现在接收所属任务的取消信号：启动前已经取消时不创建子进程，执行中取消或超时则终止进程树，等待退出或有界终止超时后结算，避免被取消的探测长期占用资源。使用隔离的短生命周期子进程验证执行中取消，连同媒体探测和语音记忆定向测试共 60/60 通过；真实长录音中途取消仍待实测。

模型管理器的 `state.json` 读取现在只把文件确实不存在视为新安装；损坏 JSON、非法结构或读取错误会中止初始化，保留原文件。管理器在状态尚未成功加载时拒绝模型操作和检查点写入，避免空状态覆盖旧记录，尤其避免用户在异常状态下点击“删除”触发模型目录删除。设置页将这种情况说明为“模型记录无法读取”。隔离目录中的损坏状态、非法结构和删除保护定向测试通过；没有读取或修复真实模型目录的状态文件。

可选 Runtime 下载现在保留已有目标文件，直到新的 `.part` 完成大小与 SHA-256 校验，再通过重命名替换。网络失败或任务取消时不再提前删除旧目标；读取文件大小时也只把 `ENOENT` 当作不存在，其他 I/O 错误继续上报。隔离目录测试覆盖失败保留、执行中取消、Windows 上成功替换及续传。现有 `AiRuntimeManager` 的运行时准备队列与 `FreeTokenManagedRuntime` 的单次准备 Promise 分别防止正常入口的同目标并发；跨进程并发下载尚未验证。

模型下载的取消信号现在从主进程接线传入转录 Runtime 准备队列，并继续传给 CUDA/Python 依赖安装、可选 Wheel 下载、tar 解包及运行时自检子进程。排队期间取消的调用会立即返回，底层串行队列仍等待当前安装退出后才处理下一项；已取消的准备不会再开始，也不会被模型管理器吞掉并错误标记为完成。隔离测试覆盖队列等待取消、执行中信号传递及模型状态拒绝误报；没有在真实已下载模型或正在运行的用户 Runtime 上尝试中断。FreeToken 自检中的短时状态探测及真实长 pip 安装取消仍待设备验证。

启动 CUDA 自检的自动修复与用户请求的模型 Runtime 准备现在共用 CUDA 安装串行队列，避免两个 pip 进程同时写同一私有目标目录。取消的排队请求在进入安装前退出；并发与取消测试通过。真正的 CUDA 安装并发、驱动异常及恢复仍需要受控设备环境验证。

CUDA 启动自检若因临时环境错误抛出异常，现在会清除失败的单次初始化 Promise，下一次调用可重新尝试；成功结果仍复用。失败后恢复的定向测试通过，真实驱动故障和重试需要设备验证。

音频设备热插拔检查现在在重新枚举完成后读取最新偏好；如果枚举失败，`Failed` 状态不会被误认成设备已拔出并清除用户选择。快速连续热插拔时，过时的枚举结果也不能覆盖较新结果。只有成功枚举且对应设备确实不在列表时，才回到系统默认。输入和输出分别判断。隔离测试覆盖失败枚举、单侧断开、枚举期间改偏好及结果乱序；真实 USB 断开、重插及双方通话听感仍待实机验证。

录音自动“废片”清理现在只采纳明确过短或静音的探测结果；FFmpeg 解码失败、超时或其他“无法读取”结果只提示人工核查，不进入自动或手动批量废片清理。设置页说明十秒阈值、容量上限与 Windows 回收站行为，录音完成提示也不再错误声称“五分钟以下”。现有自动清理走 Windows 回收站，并保留收藏、Marker 保护与至少一份录音的配额边界。本轮只改判定与文案并用隔离测试验证，没有扫描或移动用户真实录音。用户主动设置的容量上限仍会按既有规则回收未受保护的最旧录音。
