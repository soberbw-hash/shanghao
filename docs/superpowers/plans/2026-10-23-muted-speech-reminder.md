# 静音说话提醒实施与验证

用户已明确要求加入，沿用现有音频架构和设置，不等待另一次设计审批。与原整轮任务一起自检后统一审核，不发布。

## 行为

默认开启，可在语音设置关闭。只在房间中、用户手动静音、本地采集仍存活时，复用现有人声概率/近端人声分类；持续约 1.5 秒后显示“你的麦克风还处于静音状态”，播放一声低音量提示。每 60 秒最多一次，解除静音再静音、切换设备/房间不能绕过冷却。按键说话、电话模式、关闭扬声器、自动离开/静音、回声和无新检测数据时不触发。

只消费本地 VAD 的数值，不读取或存储音频正文、不上传、不解除静音。不开启新采集、ASR 或 GPU 任务。后台可走已有 Windows 通知，禁止激活/摇动窗口；通知静音，由原界面音效系统只播放一次轻提示，遵守用户音效开关及音量。

## 实施

1. `mutedSpeechReminder.ts`：纯时间门控，输入新鲜 VAD、手动静音及环境状态；先测持续/噪声/旧数据/冷却/切换，后实现。
2. `audioStore.ts`：区分明确的麦克风按钮/全局静音快捷键与自动静音；保留电话模式恢复语义。
3. `useMutedSpeechReminder.ts`：App 级订阅既有诊断，不用额外轮询；离房/设备变化重置持续段但保留冷却，清理全部订阅。
4. `settings.types.ts`、`settings-migration.ts`、`AudioSettingsCard.tsx`：默认、布尔校验、旧版本兼容与开关。
5. `uiSound.ts` 新增轻提示，既有 `app.notify` 支持可选静音，后台通知不抢焦点。

## 自检

- 纯门控及设置迁移先红后绿；真实 audioStore 的手动/自动/电话/PTT 边界。
- 隐藏 Electron 用实际麦克风处理 Worklet 的合成输入，确认静音后 VAD 继续，而发送 Track 始终 disabled；不使用用户麦克风。
- 隔离 hook 验证 toast、轻音效、后台通知各一次、禁用/PTT/电话/离房与卸载无迟到提醒。
- 对应 lint、类型和构建；整合后全量 smoke。游戏独占全屏下实际可听与系统勿扰仍需人工验证，自动化不能冒充。
