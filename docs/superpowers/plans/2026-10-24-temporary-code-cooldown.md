# 临时房间猜码保护收尾

已确认审核 P2：固定地址分钟请求额度不能替代连续失败递增冷却。只修此缺口，不发布、不重启用户应用、不改媒体路径。

1. 新增独立 `temporary-code-attempts.ts`，对已验证设备和可信网络来源分别维护有界失败状态。默认设备第 5 次失败起、网络第 20 次失败起退避 2 秒，随后每次翻倍，最多 5 分钟；30 分钟无失败过期。参数允许服务端配置。成功只清除该设备累计，不能清除共享网络的失败累计；被阻止的重试不延长冷却、不新增状态，满容量安全拒绝。
2. Runtime 的 resolve/join 与公网 broker lookup 共享该守卫。只累计错误/无效房间码，不把满员、锁定、模型失败或正常重连计作猜码。先验设备签名再使用设备 ID，保留现有未认证地址额度和挑战容量限制。
3. 先用真实 Ed25519 proof + 实际 Runtime/Broker 协议处理器、合成 socket/clock 写失败回归，覆盖分钟边界、跨网络同设备、同网络多设备、resolve/join/lookup 共用、过期/容量、成功与重连。再实现并运行临时域、永久准入、架构/类型/lint 与整合回归。
4. 提交既有“上号审核”有界复核，修复结论与真实硬件未验分开记录。
