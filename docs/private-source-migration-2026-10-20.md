# 源码私有化与公开下载迁移

## 授权与范围

用户确认自研版权均归其所有，并于 2026-10-20 明确要求“更改成不开源”。
此授权针对源码可见性、后续自研代码许可与下载入口迁移；3.4.13 新版本发布仍暂停。
不删除源代码、分支、版本归档、用户数据、模型或录音，不把整个脏工作区推送到公开仓库。

## 目标布局

- `soberbw-hash/shanghao-source`：原仓库更名并私有化，保留原仓库身份、提交历史、分支、Issues、94 个 Release 及约 28 GB 历史资产。
- `soberbw-hash/shanghao`：新建的公开下载仓库，只提交 README 和逐项允许的 9 张正式演示截图，没有应用源码及其历史。
- 原有 `releases/latest`、GitHub Releases API、v3.4.12 安装包和 `latest.yml` URL 保持不变。
- 当前正式版 v3.4.12 的 6 个资产原样迁移。不是重新构建，也不是发布 3.4.13。更早归档保留在私有源仓库，旧版公开下载链接不在本次迁移范围。

## 执行顺序与回退

1. 导出原仓库和 Release 元数据到本机迁移目录。
2. 从已校验的本机正式版缓存准备 v3.4.12 的 6 个资产，逐项比较 GitHub 的 SHA-256。
3. 创建临时公开分发仓库 `shanghao-downloads`，只上传允许的文档及演示截图；复制 v3.4.12 Release，再比较上传后的资产大小、SHA-256。
4. 匿名读取临时下载页和更新 metadata 成功后，才将原仓库改为 private、更名 `shanghao-source`，再将分发仓库更名 `shanghao`。
5. 核对仓库 ID，匿名读取私有仓库及公开仓库原核心源码路径应返回 404；公开下载 API、截图、更新 metadata 与安装器下载应成功。
6. 更新本地 origin 为私有仓库。原工作区不重建、不重置，不把本地未发布功能提交到公开下载仓库。

切换前失败则原公开仓库保持不变。切换后保留全部原资产和本机迁移副本；只修复分发仓库，不为了恢复下载重新公开源码。已有公开分叉和别人保存的副本无法由本次迁移撤回。

## 许可与后续发布

未公开的自研代码和后续版本采用根目录专有许可，npm 标记为 `UNLICENSED`，Rust 继承同一许可文件；旧 AGPL 文本保留为历史记录。第三方许可证不变，历史版本的既有授权不撤销。

私有源码仓库的 Actions 默认令牌不能写另一仓库。Release 工作流明确把安装包和演示截图发到公开下载仓库，使用 `PUBLIC_RELEASES_TOKEN`；未配置时明确停止，不在私有仓库错误发布或向客户端分发源码。可在之后获准发布时使用已授权的 GitHub CLI 手动上传经过校验的资产，或提供仅允许公开下载仓库写入的细粒度令牌。不要把私有源码仓库令牌打入应用。

公开截图作为 Release 资产上传，发布说明不再依赖私有源码的 raw URL。签名、更新配置、服务器和 CloudBase 的现有 v3.4.12 软件不因本次迁移改变。
