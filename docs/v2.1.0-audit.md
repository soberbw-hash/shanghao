# ShangHao v2.1.0 Product Audit

This document records the v2.0.0 baseline audit and the implementation status for the
single v2.1.0 release. A checked item means the repository implementation and automated
verification are complete. Real-device checks remain explicitly separate.

## Baseline Findings

| File / area                                                                            | Current behavior in v2.0.0                                                                              | Problem                                                                                                | Planned v2.1.0 change                                                                                              | Validation                                                                                          |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `apps/desktop/src/renderer/src/features/room/roomClient.ts`                            | WebRTC connection state could disable Relay before inbound RTP was proven.                              | A late fourth or fifth member could speak but fail to hear one or more existing members.               | Serialize per-peer negotiation, gate path switching on inbound RTP, and recover Relay per affected peer.           | 117 smoke tests plus all 20 directed routes in the five-peer harness pass.                          |
| `apps/desktop/src/renderer/src/features/audio/RemoteAudioMixer.ts`                     | Remote playback used a shared mixer, but source replacement needed stronger lifecycle handling.         | Muted, ended, or replaced tracks could leave a member attached to a stale playback path.               | Keep one shared mixer and make WebRTC/Relay source replacement explicit and idempotent.                            | Mixer lifecycle, late-track, and disabled-track tests pass.                                         |
| `apps/desktop/src/renderer/src/features/room/autoAway.ts`                              | Speaking, gaming, sharing, and recording prevented OS-idle away; return reused the old mute state.      | Users could remain falsely present, or return muted despite an enabled speaker.                        | Use only 1,800 seconds of Windows OS idle plus room validity; derive return mute state only from deafen.           | Boundary, manual-away, automatic-return, atomic audio-state, and reconnect tests pass.              |
| `apps/desktop/src/main/game-detection.ts` and settings files                           | Detection launched unconditionally and lacked a live master switch.                                     | Disabling detection could not stop PowerShell work or clear stale game state.                          | Add a migrated master setting with immediate start, stop, clear, and eight-second polling.                         | Settings migration, structured process matching, and lifecycle smoke tests pass.                    |
| UI sound settings, `uiSound.ts`, and `useUiFeedbackSounds.ts`                          | Hidden per-event booleans coexisted with partially exposed settings.                                    | Persisted fields could silently override the visible master controls.                                  | Keep only a master switch and volume; add distinct self/member enter and leave assets with snapshot deduplication. | Settings and asset tests pass; all four semantic sound paths build into the renderer.               |
| `motionSystem.ts`, `motionPresets.ts`, shared motion constants, and CSS                | GSAP, Framer Motion, and CSS used overlapping tokens and some hard-coded timing.                        | Motion could feel inconsistent or allow multiple engines to compete for one transform.                 | Establish one vocabulary, explicit engine ownership, interruptible transitions, and reduced-motion variants.       | Lint, motion static audit, dialog interruption tests, and automated screenshot capture pass.        |
| `TeamIsland.tsx` and new `SceneCharacter*` / character runtime modules                 | Scene layout, movement, character rendering, labels, reactions, and personality lived in one component. | Changes were difficult to isolate and could regress seat movement or character rendering.              | Split character rendering, labels, reactions, personality, and motion runtime while preserving scene semantics.    | Room layout, seat arbitration, pathfinding, entry, interruption, and motion tests pass.             |
| Overlay renderer and room state updates                                                | Capsule-level entrance could replay when member state changed.                                          | A mute or speaker update could visually restart the whole overlay.                                     | Keep the container mounted and animate only the affected avatar or state region.                                   | Overlay entrance/state smoke tests and visual capture pass.                                         |
| `RoomPage.tsx`, `ScreenShareManager.ts`, and viewer preload                            | Screen capture, track cleanup, detached viewing, and UI ownership were spread across several layers.    | Cancellation, repeated sharing, or viewer teardown could leave stale tracks and excess preload access. | Centralize capture lifecycle and expose a minimal viewer-only preload.                                             | Manager cleanup/system-audio tests pass; real two-device sharing is not verified.                   |
| `packages/signaling/src/server.ts`, protocol, and `session-token-store.ts`             | A reconnecting socket could replace a peer using identifiers alone.                                     | Knowing a peer identifier was too much authority for session replacement.                              | Issue, rotate, expire, and invalidate opaque reconnect credentials without logging raw tokens.                     | Valid, invalid, expired, and old-socket replacement protocol tests pass.                            |
| `apps/desktop/src/main/index.ts`, `tests/visual/capture-ui.ts`, and `tsup.config.ts`   | Formal main-process code contained visual automation behavior.                                          | Test-only clicks and delays could accidentally ship in production.                                     | Move capture automation to the test bundle and load it only in development when explicitly requested.              | Production packaging excludes `dist-electron/tests`; the 1440p home and settings capture completes. |
| `scripts/deploy-relay-ubuntu.sh`                                                       | Deployment could overwrite `/etc/caddy/Caddyfile`.                                                      | Existing sites and unrelated Caddy configuration could be destroyed.                                   | Install one `conf.d` fragment with backup, validation, rollback, idempotency, and reload.                          | Bash syntax and static tests pass; production-server execution is not verified.                     |
| Builder config, package scripts, README, release notes, and the obsolete `.icns` asset | macOS targets and metadata remained despite Windows being the only supported release platform.          | Release promises and packaged assets did not match actual support.                                     | Remove macOS build targets/assets and publish only Windows x64 NSIS artifacts.                                     | Windows installer, blockmap, `latest.yml`, packaged runtime, release metadata, and checksums pass.  |
| `CHANGELOG.md`, architecture, motion guidelines, release notes, and this audit         | v2.1.0 lacked a consolidated implementation and ownership record.                                       | Future changes could reintroduce architectural overlap or unsupported claims.                          | Document changes, module boundaries, runtime flows, motion rules, verification, and unverified gates.              | Prettier and release metadata verification pass.                                                    |
