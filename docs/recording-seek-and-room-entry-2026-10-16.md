# 录音进度条重复区块与进房减负（2026-10-16）

## 原因与修复

### 录音库

- 录音库条目的 `id` 和 `recordingId` 相同，精彩时刻与模型对比两个相邻组件原先都以它们作为 React key。对比打开后刷新播放时间，会进入重复 key 的不受支持的协调行为，出现旧区块残留；截图中各区块都是同一条 00:01:01，顶部仍显示 1 个标记，与此一致。
- 继承本地已有的 `clips:` / `comparison:` 前缀修复，进一步将两个区域放到独立的固定槽位，避免同级身份冲突。没有删除、合并或重写用户标记文件。
- 播放进度条只修改播放器 `currentTime` 与界面播放位置，没有调用新增/保存标记接口。给实时录音 store 再加防线：只在 Recording 状态接受新 ID，重复 ID 不重复加入。原有的录音中自动游戏标记行为保留。
- 对比页移除“在播放时间轴添加标记”的错误提示，改为“暂无录音标记”。

### 进入房间

- 可选预热原先只检查焦点、可见性和浏览器空闲。加入流程存在网络/设备异步等待，这些空隙可能被当成空闲，继续同步合成提示音、启动图片解码或导入设置模块，与进房准备竞争。
- 首页点击进入后，在初始化输出上下文及枚举设备前设置 starting；失败或提前返回会恢复 idle，连续点击也有同步状态保护。
- App 把进房动作与路由变化同步给独立的可选预热调度器。starting/joining 时不调度，路由/动作变化后预留 1200 ms，再按原来的可见性、焦点、空闲预算继续。等待可取消，无轮询；不接入实时媒体、连接或录音生命周期。
- 提前预生成进房及录音提示音，减少冷启动时才合成的机会。自动录音原先在进房后约 450 ms 再播一次开始提示，现保留状态/通知、取消这次重复启动声音；手动录音的声音保留。没有改变用户音量设置。

- 修改涉及的源码与新增测试定向 ESLint：通过。
- 新增调度测试覆盖进房期间不运行预热、不轮询，进入后 1200 ms 保护、隐藏/取消与订阅释放。标记测试覆盖非录音拒绝、录音新增、相同 ID 去重、保存阶段拒绝。
- 隔离 Electron 实际 React 页面：连续拖动/点击进度 120 次，切换模型对比 8 次；每次检查播放器确实跳转、精彩时刻只有一个、时间轴标记一个；保存操作 0 次，夹具标记数据未改变。命令：`corepack pnpm --dir apps/desktop exec electron tests/electron-recording-seek-regression.cjs`。
- Electron 夹具使用新建临时 profile、隐藏窗口和模拟桌面 API；不访问真实录音、不发起转录、不占麦克风，不抢用户窗口。
