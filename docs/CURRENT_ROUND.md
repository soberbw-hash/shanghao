# ShangHao 3.0.4 发布记录

## 当前基线与边界

- 当前正式代码基线：ShangHao 3.0.4。
- 本轮目标：完成本地改动收口、Windows 安装包构建、GitHub 推送和 v3.0.4 Release。
- 发布前仍需完成自动化验证和目标 Windows 设备上的人工审核；未通过的边界不冒充已验证。
- 不删除用户录音、模型、配置、缓存或既有能力；本地 AI 结果默认留在本机。

## 当前架构

- Electron 主进程负责窗口、IPC、录音文件、AI Runtime、模型下载、诊断和 Windows 集成。
- Renderer 使用 React、Zustand、GSAP/Framer Motion 和已有 `uisfx`，RoomPage 继续通过 `roomClient` 组合房间生命周期、媒体、Peer Recovery、屏幕分享和 UI 状态。
- Shared、WebRTC、Recording、Signaling 和 UI 包保持清晰边界；只有具有完整职责的模块才拆分。
- 五人固定房间继续使用 WebRTC Mesh，并保留信令音频/屏幕兜底、ICE/TURN、AEC、DeepFilterNet、VAD、响度平衡和资源调度。

## 已完成功能与本轮已接入

- 账号系统、访客模式、头像、登录安全边界和 Supabase 服务端账号接口已在 3.0.3 基线中。
- 录音库支持本地保存、播放、收藏、标记、重命名、批量删除、容量清理和时间点回放。
- 语音记忆支持录音转录、说话人、时间轴、章节、精彩片段、本地整理、本地搜索和带来源的 AI 问答。
- 本轮增加每条录音的 ASR 有效运行耗时字段：只累计模型实际运行窗口，暂停、排队、格式转换和整理不计入。
- 本轮增加“语音库 → 模型测试”开发界面：选择已安装模型和录音，按顺序逐条运行，支持暂停、继续、停止，并显示成功数、总有效转录时间和平均耗时。
- UI SFX 已接入 `uisfx`，保留音效开关、统一音量和输出设备路由；快捷消息按开麦、询问、等待、确认等语义分配轻反馈。
- 设置中已加入首层“ShangHao 体检”摘要，详细 WebRTC、Relay、GPU、音频、屏幕分享和 AI 诊断仍可展开查看，并保留复制诊断信息。

## 当前 AI 模型状态

- ASR 支持多模型独立下载、运行时检查、完整性校验、暂停/继续和 A/B 结果保留。
- Qwen 整理与 ASR 已拆为独立任务；整理可以重新执行，不应重新触发 ASR。
- 模型测试不提供“速度优先/均衡/效果优先”档位；用户手动选择模型并比较真实字幕、说话人、分段和耗时。
- 本机仓库的 `apps/desktop/resources/ai` 目前只有运行时清单；实际模型位于用户模型目录，不随代码同步删除或覆盖。

## 录音系统与 AI 语音记忆

- 录音、转录、整理均为本地可控流程；暂停不会自动转录下一条。
- 语音记忆来源必须绑定真实录音、日期、说话人和时间点；问答无依据时不得编造来源。
- 点击记忆来源应回到原录音对应时间点，继续保留可核实的时间轴和字幕入口。
- “整理”和“上传”必须保持两个独立状态。当前仓库已有本地整理链路，但没有成熟的录音记忆上传服务端协议；在协议补齐前不得显示虚假的“已上传”，也不得因整理自动上传。

## 账号、屏幕共享与 CUDA Runtime

- 账号凭据和刷新令牌不进入 Renderer、日志或普通 Relay 消息；服务端密钥只留在 Relay 环境变量。
- 屏幕共享继续支持 720p、1080p、1440p 请求、WebRTC 视频、兜底画面、观看者状态和轨道清理；不得用本轮 UI 优化降低分享质量。
- CUDA/GPU 状态通过 RuntimeHealth 和 AI Runtime 诊断展示；模型完整性失败只影响对应 AI 任务，不应阻断主客户端、麦克风、WebRTC、录音或屏幕分享。

## 当前不能破坏的能力

- 五人长时间语音、进退房恢复、短暂断网恢复、AEC/DeepFilter/VAD、录音写入和播放。
- 1440p 与长时间屏幕分享、音频/视频兜底、显存和 AudioNode 清理。
- AI 任务暂停/恢复、断点、模型版本绑定、既有转录结果和本地数据安全。
- 动画丰富度、合成层移动、`prefers-reduced-motion`、UI 音效开关/音量、快捷消息和普通设置操作。

## 3.0.4 发布重点

- 让动画节奏更统一、更轻、更自然；只在已有视觉语言中做合成层和状态反馈优化，不删除现有动态效果。
- 扩展语义化 UI 音效和快捷消息差异，同时避免打扰语音聊天。
- 继续完善模型测试结果保留、录音整理/上传状态解耦、来源可回放和体检摘要。
- 收口内存、GPU、音频设备、WebRTC、监听器、定时器、录音文件和 AI 队列的长期稳定性。

## 发布后待办

- 在不自动上传录音的前提下，设计并验证独立的服务端录音记忆上传协议、权限和失败重试。
- 在真实 Windows 设备完成多人长时语音、1440p 分享、长录音、连续模型测试、后台模型下载和游戏并行运行实测。
- 补齐模型测试的端到端人工验收记录，并比较中文、英文、中英混合、方言、说话人和分段质量。
- 继续维护本文件，使下一次 Codex 接手时以实际代码和验证结果为准；本次发布后等待用户审核，不自动开始下一轮。

## 验证边界

- 当前已验证：依赖补齐后全工作区 typecheck 通过，3.0.3 基线 smoke tests 433/433 通过，`git diff --check` 通过。
- 自动化通过不等于真实设备音质、多人听感、FPS、显存曲线、网络恢复和长时泄漏已经通过；这些必须在目标家用电脑上手动验证。
