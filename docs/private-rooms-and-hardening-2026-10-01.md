# 私人房间与底层收口记录（2026-10-01）

## 基线与范围

本轮基于本地 v3.3.1 工作区，承接用户的 18 项治理建议及动态私人房间需求。开发阶段完成后，用户明确授权先发布 3.4.0、后续继续深入审查；本记录保留本地开发证据，线上发布结果另行记录。不清理真实用户数据。

## 私人房间已实现

1. **永久身份与频道号分离。** 六位频道号以字符串保存，支持前导零；内部使用不可变 `room_` UUID。删除后频道号冷却 30 天，重新使用会得到新 UUID，不能继承旧房间数据。
2. **创建与进入。** 每个已登录账号最多创建三个房间；20 个内置 SVG 图标、随机默认图标、默认名称、随机可用频道号及提交时唯一性校验。通过频道号查找后预览并明确点击加入，没有公开房间列表或自动加入。
3. **最近、收藏与我的房间。** 成功加入后才保存最近记录与上次房间，收藏由用户操作；记录按账号和服务器隔离。只刷新有限数量的可见记录，不轮询全目录。
4. **五人容量与房主权限。** 在线人数包含房主，房主也不能成为第六人。持久化账号身份决定所有权，不能通过 Renderer 的昵称或 profileId 冒充。房主离线不关闭房间；房主可编辑名称、图标，移出成员、封禁、解封及删除房间。
5. **持久化与资源释放。** 房间、封禁和频道号冷却期原子保存；空房间释放在线运行状态，保留元数据。损坏文件拒绝启动或写入，不用空目录覆盖。服务器采用单写入进程，部署前必须配置持久化目录。
6. **房间切换与数据归属。** 进入新房间前完成旧房间录音收尾和分享、连接清理。聊天、收藏提示、房间报告、录音和 AI 任务使用真实 RoomID；录音元数据同时保留录制时房间名称。旧一号房、二号房的数据仍可读取，不再作为正式首页入口。
7. **明确终止状态。** 房间不存在、被删除、移出、封禁或容量已满时终止加入重试，避免无限重连。重新连接的旧会话不会重复占座；只有容量不足时才释放已经离线的宽限席位。

部署与回退要求见 [私人房间服务器操作说明](private-room-server-operations.md)。本地功能与线上启用是独立步骤；只有正式部署和健康检查完成后才能确认线上可用。

## 18 项治理建议如何收口

| 建议                         | 本轮结果与边界                                                                                                                                                                                                                                                                                                                               |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1–2：核心模块与 Voice Memory | 独立提取转录准备、分段执行重试、整理任务与共享下载流程；服务入口从约 2915 行降到 2044 行。整理模块自己管理分块、归并、检查点与结果规范化，入口负责协调，没有把状态通过一组互相调用的碎片函数搬来搬去。其余成熟媒体核心保留。                                                                                                                 |
| 3：资源所有权                | 录音收尾登记器按身份注销，重复完成请求共享一份收尾任务；旧回调不能注销新 owner。Marker 保存失败保留录音与时间线，允许重试。AI 关闭时取消任务、移除监听和定时器。                                                                                                                                                                             |
| 4–5：事实来源与状态投影      | 服务端成员与持久化房间信息决定房间身份、人数、所有权和准入；客户端成员映射提取为视图投影，删除未使用的固定房间人数副本。既有音频 Desired / Applied / Observed 诊断继续保留，不改写处理器和 Track 路径。录音以实际完成、元数据提交与所属房间为准。                                                                                            |
| 6：调度与容量                | 模型和 Runtime 下载共用限速与压力等待；等待有截止时间，排队调用者可独立取消。ASR 的 FFmpeg 转换与实际推理现在占用同一计算租约，不能在 LLM 占槽时提前开始转换。系统可用内存低于 2 GiB 时降级资源模式。Runtime 安装仍由原有串行 owner 和跨进程资源锁管理；没有把 I/O 安装等同于 GPU 推理，也没有新增显存自动探测或声称所有 FFmpeg 都占同一槽。 |
| 7：公共保护能力              | 提取可取消等待和独立等待共享任务的公共能力；Runtime 组件下载复用有界下载、校验和共享限速。既有原子文件、进程树终止和资源锁继续使用。                                                                                                                                                                                                         |
| 8：复杂 IPC 边界             | Benchmark clips 的数量、嵌套区间、时间顺序、文本、关键词和环境字段逐层验证；房间和存储提供显式类型化能力，没有万能 invoke。命令、响应和本地历史均有大小或数量上限。                                                                                                                                                                          |
| 9：体验减负                  | 首页只订阅所需设置；隐藏存储页拒绝迟到响应；房间历史刷新限制数量与并发。房间目录索引按提交版本更新，不在每次查询重新构造。没有增加常驻扫描或动画。                                                                                                                                                                                           |
| 10–11：存储与垃圾            | 通用设置增加按需查看模型、Runtime、录音、更新缓存、临时文件占用；扫描不读取文件内容、不跟随链接且有时间和数量界限。清理只能处理七天前的 ASR 临时 WAV，每次最多 100 个；仍运行或权限不确定的 PID 保留。模型、录音、可续传下载和待安装更新保留。                                                                                               |
| 12：安全存储                 | 房间目录使用版本化、串行事务、提交前校验与原子落盘；导航历史按账号和服务器独立、串行写入，重复 ID、损坏或超过 256 KiB 的文件不能被后续操作覆盖。录音元数据不允许被重新绑定到别的房间。已有账号、设置与 AI 存储保护继续使用。                                                                                                                 |
| 13：废弃实现                 | 删除首页固定房间选择、隐式默认加入和未使用的人数订阅；保留旧文件读取和旧开发测试协议，不以旧日期作为删除证据。没有删除用户模型或仍有效的 Supabase 会话兼容路径。                                                                                                                                                                             |
| 14：大型依赖                 | 本轮未增加大型 SDK、二进制或模型，也未替换 FFmpeg。沿用上一轮的一份 FFmpeg、目标平台资源排除和包体积守卫；下一次获准正式打包时再核算真实产物，旧包数字不是本轮测量。                                                                                                                                                                         |
| 15：错误处理                 | 私人房间使用固定错误码转可读提示，区分失效会话、服务器尚未支持、暂时故障和终止准入；录音与 AI 的失败状态和取消结果跟实际任务一致。确定性的 Runtime 故障停止重试，异常输出保留评测证据但不冒充成功正文。                                                                                                                                      |
| 16：够用的诊断               | 沿用有界 Room Session、Peer / Audio / AI 调度关联记录；没有新增正文、凭据采集或遥测平台。自动化状态不等于远端听感。                                                                                                                                                                                                                          |
| 17：权限范围                 | 上轮已经明确系统级写入与普通业务的权限需求，见 [权限审计](windows-admin-privilege-audit-v3.2.0.md)。本轮不改变已安装程序执行级别。普通账号隔离验收及固定命令提权 helper 属于后续权限迁移，不能把文档调查说成已经降权。                                                                                                                       |
| 18：比例验证                 | 本轮实际涉及信令、录音、AI、持久化和 UI，故做定向失败注入、全量 smoke、五人媒体回归、类型检查、Lint 与普通构建。没有重复真实长录音模型评测或重新安装 CUDA Runtime。                                                                                                                                                                          |

## 架构护栏

- `docs/architecture-budgets.json` 冻结本轮审查后的核心模块及 CSS 上限。
- `scripts/check-architecture-ratchet.mjs` 比对提交基线，已有上限只能持平或下降；仍存在的文件不能删除预算逃避检查。首次采用与原先提交中的 inline guard 比较。
- CI 和 Release 检查提交前后预算；本地 smoke 检查实际文件长度。新职责必须先形成清楚的模块边界，不通过抬高旧上限继续增长。
- Rust 职责与原有原生层质量检查保持不变，本轮没有新增 Rust 业务或拆动画 CSS。
