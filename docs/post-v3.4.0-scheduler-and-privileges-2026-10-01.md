# v3.4.0 发布后：调度与权限收口

本记录对应 2026-10-01 本地接续修改，正式版本号仍为 3.4.0。本轮没有重新打包 EXE、推送、发布或部署。已上线的私人房间和 3.4.0 安装包仍以 [发布核对](release-verification-v3.4.0.md) 为准。

## 1. 重任务的统一入口

生产 Main 显式共享 `mainResourceScheduler`；Zustand 不新增一份后台资源事实状态。调度器负责准入、压力、租约、等待与关闭，实际文件、子进程和模型资源仍由原拥有者收尾。

| 资源         | 已接入的路径                                                                                              | 归属与约束                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| AI 计算      | ASR、整理、问答使用原独占计算槽                                                                           | 32 个等待上限、15 分钟等待期限；取消不释放别人的租约                                        |
| CPU/磁盘后台 | 模型完整性核对、模型 Runtime 准备、CUDA 修复、FreeToken 准备、捆绑 runner 准备、ASR FFmpeg 转换、录音扫描 | 一个后台拥有者；ASR 转换优先于下一次安装；32 个等待上限、90 秒等待期限、90 分钟执行取消期限 |
| 前台录音     | 录音 AAC 保存和媒体头探测                                                                                 | 最多 4 个前台拥有者，单线程编码；不被长安装阻塞，不中断已有部分安装                         |
| 下载带宽     | 模型、可选 Runtime 组件与 FreeToken 文件传输                                                              | 同一聚合预算：正常 64 MiB/s，游戏/通话 8 MiB/s，恢复压力 1 MiB/s；关键压力期间等待有界      |
| 低优先级维护 | 录音静音扫描                                                                                              | 录音、关键网络压力、CPU 或内存压力时让路；取消或探测失败不产生自动删除候选                  |

执行期限通知拥有者取消；槽位直到实际操作结束才释放。原有跨进程下载锁、完整性检查与安装目标锁继续负责磁盘资源，不被进程内调度器替代。录音输入在成功输出前保留；模型 ready marker 通过现有原子文件能力提交。

CPU、可用内存、CUDA device 0 的可用显存按需检查。`nvidia-smi` 异步执行最多 2 秒、输出最多 4096 字节；并发请求合并，结果及失败缓存 15 秒，没有常驻采样定时器。第一份 CPU 样本和缺失 GPU 数据是未知。高 CPU、显存不足或 RAM 压力降低 AI 资源模式，房间内极高 CPU 压力阻止自动计算，极低 RAM 阻止后台准备；用户主动请求保留现有低资源路径。这是简单准入保护，不是模型峰值显存预测，也不能保证外部游戏或驱动变化不会造成 OOM。

收尾回归曾发现：容量刷新被放到登记队列前，以及独立服务实例误用全局调度器。前者延迟排队状态，后者让一次失败阻塞后续测试。已改为生产显式注入共享实例、独立实例各自隔离，登记租约后刷新容量，并覆盖刷新期间取消的释放路径。没有提高原架构上限。

## 2. 管理员权限范围

本地打包配置改为 `asInvoker`、`uiAccess=false`。普通房间、聊天、WebRTC、音频、录音、AI、ADB、用户目录存储和只读系统检查继续留在原进程；未重写媒体路径。

防火墙修复/移除、快捷方式箭头隐藏/恢复使用固定的四种系统命令。Renderer 不传脚本或 EXE 路径；Main 校验当前主窗口及其主 Frame，自己指定进程路径。辅助 PowerShell 按需 `RunAs`，隐藏运行，包含过期检查和执行超时。UAC 取消、超时、执行失败有独立的用户错误；完成后重新读取系统状态。

启动不再因规则缺失或检查失败自动弹 UAC。旧开机任务仍只尝试删除准确的 `ShangHao Auto Start`；普通权限删除被拒绝时，不写迁移成功，不为这项历史清理自动提权。需要管理员的遗留任务仍由既有卸载清理或显式系统维护处理。Windows 对高权限游戏、受保护进程和组织策略的限制保留现有降级边界，需要对应环境验收。

已检查本地 electron-builder 26.15.7 的 NSIS `StartApp`：使用 `StdUtils.ExecShellAsUser` 从安装器启动普通用户程序；electron-updater 仍负责需要管理员的安装位置。源码检查不代表实际旧客户端安装重启。下一次正式包的执行级别检查现在要求真实 EXE 含 `asInvoker` 并拒绝 `requireAdministrator/highestAvailable`；本轮没有生成新包，不能声称已验证新 EXE。

## 3. 同时关闭的已知错误

CloudBase 身份查询明确的无效令牌/JWT HTTP 400 被正确识别为失效凭据，未知 400 和 503 仍作为暂时服务错误。两处身份查询均有定向测试，未放宽身份准入。线上已发布服务尚未部署这项后续修复。

屏幕捕获和 AudioWorklet 原生测试入口新增独立临时 `userData` 与 `sessionData`。退出只清本次生成并校验归属的临时目录；锁定缓存可以留下。没有拿真实账号、录音或模型目录做夹具。
