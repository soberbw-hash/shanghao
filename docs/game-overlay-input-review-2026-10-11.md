# 游戏悬浮窗与非主动弹窗检查 · 2026-10-11

## 反馈与结论边界

用户朋友在英雄联盟中开启悬浮窗、未修改默认快捷键，没有收到消息或被敲一下，却反馈软件弹到前面及鼠标卡顿。敲一下是用户要求的主动提醒，其拉起窗口、响铃与晃动行为保留。

本轮修复确认存在的鼠标拦截、周期窗口排序和后台恢复聚焦路径。随后收到朋友 3.4.5 的诊断包，检查结果见下方；仍没有游戏帧时间或开关悬浮窗对照，不能确认那次事件的唯一原因，也不能把前一轮本机低 CPU／无明显卡顿结论推广到朋友设备。

## 已修改的本地源码

1. **游戏中的悬浮窗保持鼠标穿透。** 检测到游戏运行后清除悬停／拖动交互、停止 80 ms 鼠标位置查询，不转发鼠标移动给 Renderer。迟到的交互请求不能重新接管鼠标；游戏结束后恢复原来的悬停调节。游戏中仍展示语音状态，需要调节好友音量时可打开主界面。
2. **移除持续的窗口排序。** 不再每两秒调用 `setAlwaysOnTop` 与 `moveTop`，也不在 blur 或加载完成后额外反复置顶。初次创建仍设置不可聚焦的置顶状态，显示使用 `showInactive`；显示器变化仅在置顶状态确实丢失时重新设置。`moveTop` 操作的是窗口 Z 顺序，单凭它不能证明主窗口抢了焦点，参见 [Electron BrowserWindow 文档](https://www.electronjs.org/docs/latest/api/browser-window#winmovetop)。
3. **备用页和迟到启动回调不主动聚焦。** Renderer 失败／退出时仍加载错误说明，但不调用 show/focus；窗口初次显示只进行一次非激活显示。已隐藏、最小化或销毁后，迟到 ready 与 1.5 秒计时器不能重新弹出。
4. **补充有界窗口诊断。** 记录 show/hide/focus/blur/minimize/restore，以及可见、聚焦、最小化布尔状态，每分钟最多 32 条。没有鼠标坐标、按键、聊天或音频内容，用于后续对照异常恢复日志。

主窗口的显式托盘／通知点击、重复启动和深链接激活仍保留。敲一下的原提醒路径未改变。默认设置不启用侧键快捷消息或按住静音，本轮没有将默认鼠标问题归因于这些未启用的钩子，也没有修改 uiohook 二进制、驱动、鼠标回报率或系统服务。

### 诊断导出缺陷与修复

运行历史源有 160 个样本，导出数组却取最早 100 个，只到 12:44:21；约 13:52 导出时，flight recorder 也只保留到 13:44:18。根因为通用脱敏函数使用 `slice(0, 100)`，丢掉了时间线尾部；因此该包不能完整对照最近弹窗事件。

本地修复让已知时间线／样本数组保留最近 100 项，继续按时间正序导出并逐项脱敏。根数组通过已知文件名识别，普通列表仍保留前 100 项，源数组不修改；没有扩大缓存、记录聊天内容或改变实时路径。9 项诊断定向检查通过，覆盖嵌套与根时间线、隐私脱敏、数量边界和普通列表行为。该修复尚未打包发布，不能恢复原包里已经遗漏的记录。

发现当前 HWND 的 SMALL/BIG 图标位图都为 1254 × 1254：`getWindowIcon` 优先加载原稿 PNG。Electron 42 对 PNG-backed NativeImage 的 GetHICON 不按请求尺寸缩放，而 ICO-backed 路径会调用 LoadImage 读取所需尺寸。本地已改 Windows 优先直接加载多尺寸 ICO；ICO 缺失时才将原稿等比缩为 32 px 兜底，原稿和 EXE 未修改。[Electron NativeImage 实现](https://github.com/electron/electron/blob/v42.0.0/shell/common/api/electron_api_native_image.cc)
