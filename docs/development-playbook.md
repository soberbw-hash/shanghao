# 上号版本开发与验证手册

这份手册是每个版本都要读取的常驻入口。它记录可复用的方法，不把某次审计的进度或测试结果当作以后版本的结论。安全边界以仓库根目录的 `AGENTS.md` 为准；当前执行顺序见 [剩余工作清单](remaining-work.md)，详细证据分别见 [架构稳定性进度](architecture-stability-progress-2026-09-27.md) 与 [体积审计](package-size-audit-2026-09-27.md)。

## 每次开始：先确定真正的基线

1. 读取 `AGENTS.md`，执行 `git status`、`git diff`、`git diff --staged`。本地工作区是最新基线，先辨认已有修改的归属和风险，再继续编辑；不使用远端覆盖本地。
2. 核对本次需求涉及的代码、已有测试及上次未完成的证据。对于可能已经修复的 UI 或媒体问题，先检查当前实现与实际界面，避免重复改写。
3. 给本次改动标注影响面：纯文案/视觉、设置与持久化、账号/更新、录音/AI、实时语音/信令/分享。影响面决定验证范围，不因版本号变化机械重做全库审计。

## 实现时优先守住四条边界

文件导出新增路径需同时核对源文件只读、重名不覆盖、真实路径与符号链接边界、临时文件收尾和任务取消。Electron 导出/托盘检查必须使用独立 profile；原生调用探针与系统通知到达、第三方拖放分别记录，不能混称端到端通过。

- **资源归属：**房间、Peer、Track、音频处理器、录音流、下载与 AI Job 都要有明确拥有者。跨 `await`、重连、取消和销毁后，旧任务先核对会话或任务代际，再提交状态或释放资源；旧任务不能清理新任务的资源。以失败注入覆盖迟到回调、重复操作和部分成功。
- **用户数据：**只有 `ENOENT` 才代表文件不存在。读到损坏、未知版本或权限错误时保留原文件并拒绝可能覆盖它的写入；迁移先校验源数据，再用临时文件和原子替换提交。测试使用独立临时 `userData`，绝不拿真实聊天、录音、Marker、模型或更新缓存做破坏性夹具。
- **实时体验：**定位语音故障时先按成员、按链路区分采集、处理、发送、接收与播放，再看 Relay/TURN 恢复；不因局部故障重置全房。AI 与下载必须给通话和录音让路。保持已验证的 WebRTC、DeepFilter、VAD 路径，只有明确缺陷和对应验证才修改。
- **长任务边界：**pip、FFmpeg、模型下载和其他子进程应有取消、超时、进程树收尾及有界输出；先用临时目录里的可丢弃夹具注入长时间运行、并发与失败，再考虑真实 Runtime。相同不可变资源的跨进程实验不能替代跨版本、真实网络或驱动故障验收。
- **证据边界：**测试通过只说明测试覆盖的条件。把“手机有波形”“电脑有输入”“已发布到房间”“朋友听到”分开记录；把自动化五人链路和五台真实设备分开记录；把更新文件校验和旧版客户端点击安装重启分开记录。

## 按风险选最小验证

| 改动范围                                 | 完成该阶段时的验证                                                                                                                                                |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文案、局部 UI、纯视觉动画                | 对应页面/组件检查；有逻辑变化时运行定向测试和 `corepack pnpm typecheck`。动画还要检查隐藏页暂停与低性能设备表现。                                                 |
| 设置、账号、持久化、下载、AI Job         | 定向正常/失败/中断/重入测试、N-1 数据夹具（涉及格式时）、`corepack pnpm typecheck`。所有写盘测试只在隔离目录运行。                                                |
| 房间、信令、音频、屏幕分享、录音生命周期 | 定向竞态测试、`corepack pnpm --dir apps/desktop test:smoke`、`corepack pnpm test:five-peer-audio`、`corepack pnpm test:five-peer-media`，再按变更做相关设备验收。 |
| 构建、打包依赖、资源规则                 | `corepack pnpm build` 和相应资源校验；正式打包仅在本次任务获得授权时运行。对真实安装包生成体积报告并与预算及上一正式基线比较。                                    |

测试失败先定位原因，修复后重跑受影响的最小集合。阶段完成时再做全量验证；不把重复运行同一大套测试当作额外证据。需要正式发布时，以本次明确授权和发布流程为准，并检查当前云端版本，不从本地版本号推断最新 Release。

## 体积与长期存储的复用办法

- 安装包、解压后文件、`app.asar`、Renderer 资源和 `%LOCALAPPDATA%` 缓存分别计量；不要把归档内的逻辑大小再次加进物理总量，也不要用一次候选包大小冒充后续代码的大小。
- 已有 `scripts/report-package-size.mjs`、`scripts/check-package-size.mjs`、`docs/package-size-budget.json` 和 v3.2.2 基线。仅在打包内容变化或正式发布时用**该次实际产物**重新生成报告、核对预算及主要增减项；日常 UI 改动不重做 32 项系统审计。
- 发现旧目录、旧提交日期或大 `.part` 文件，先查引用、安装包内容、运行时用途和恢复/续传语义。时间久不是可删除证据；未经用户明确决策不清理真实模型、录音和更新缓存。

## 私人房间与本轮可复用保护

- 房间存储、聊天、录音和 AI 任务使用永久 RoomID；频道号仅负责查找。加入成功后才记最近记录，查找、收藏或创建不能自动加入。切换先结束旧房间资源，失败时不能把旧录音重新标记为新房间。
- 修改房间身份或准入时运行 `private-room-directory`、`private-room-signaling`、`private-rooms-client` 定向测试，覆盖五人容量、非房主拒绝、重启、封禁和频道号冷却后新 UUID。线上目录必须持久化且只有一个服务进程写入，见 [操作说明](private-room-server-operations.md)。
- React StrictMode 会执行 effect 清理。原生 `<dialog>` 的清理 `close()` 不能经 `onClose` 触发父组件卸载；用显式关闭按钮及 `onCancel` 管理退出，并用实际浏览器检查第一次打开、重复打开与嵌套弹窗。
- ASR 转换与推理需要同一计算租约时，在最外层获取、最外层 finally 释放；内部 worker 不再二次获取，避免排队死锁。取消排队者不能释放正在运行的别人的租约，迟到结果也不能写完成状态。
- 过期临时文件清理同时检查归属、年龄、活动进程和数量界限；PID 仍运行或权限不确定时保留。按日期或扩展名直接清模型 `.part`、安装包与录音不属于安全清理。
- 架构预算位于 `docs/architecture-budgets.json`，本地运行 `node scripts/check-architecture-ratchet.mjs` 比对已提交基线。旧预算只降不升；删仍存在文件的预算也会失败。新模块先审查职责，不能单纯移动代码绕过护栏。计行方式包含末尾换行，采用 smoke 的相同算法。

## 每版留下什么，下一版读什么

### 官方图标的永久来源

- 品牌图标只能采用用户提供的原文件，禁止重画、裁切、加光或替换成相似耳机图。先读 [图标规范](branding/README.md)，从唯一来源 `docs/branding/github-avatar.png` 生成各端资源。
- 每版安装包保留 `resources/build/icon-master.png` 与 `brand-source.json`，核对原图 SHA-256 和尺寸；用户新增勾边或高光时必须导入实际原文件，不能从聊天预览截图恢复。
- 窗口图标、EXE 内嵌图标、快捷方式图标与 Windows 固定项是不同层次。开发运行器的裸 `electron.exe` 不应作为上号入口；窗口必须同时设置重新启动名称和携带项目目录的命令。GitHub README 的本地资源更新不等于远端已发布。

### 调度与普通权限的复用经验

- 生产 Main 显式注入同一个 `mainResourceScheduler`，独立服务夹具使用独立调度器。不要让测试实例依赖全局队列状态；前一个失败的测试留下租约时，会拖住后续不相关任务。
- 先登记计算租约和排队状态，再在租约内刷新容量并复核准入。异步 GPU 检测不能延后 UI 的排队反馈；刷新失败或取消必须释放该租约。压力通知已有唯一发布者时，不重复订阅内部取消而多发同一个状态。
- Runtime 准备使用独立的 CPU/磁盘通道，ASR/LLM 使用独占计算通道；Runtime 在计算租约内准备时不能再次取得同一计算槽。等待、取消和关闭都有明确期限；取消先通知拥有者收尾，不能直接把槽位交给别人。
- 用户录音保存不能排在长安装后面。保留专用的有界前台通道和单线程编码；可丢弃的后台扫描可以取消，部分安装不能为了抢占被随意中断。CPU/VRAM 只按需采样，合并并发和短期缓存；未知数据不能当成零容量，也不承诺只靠阈值保证任意模型不发生 OOM。
- 主程序普通权限，系统写入只接受 Main 自己生成的固定操作与目标路径，显式点击才弹 UAC。启动读取失败不能自动修复系统。UAC 取消、超时、操作失败与操作后只读核对分别处理；NSIS 普通用户启动模板的存在不等于旧版升级已实测。
- 每一个 Electron 原生测试入口都要在 `app.whenReady()` 前隔离 `userData` 和 `sessionData`。清理只针对本次创建、核对过归属且没有目录重定向的临时目录；锁定缓存可保留，不能重试删除别的路径。

每个版本在对应记录中简要留下：变更范围、修复的根因、定向与全量测试结果、真实设备结论、尚未验证项、体积报告所对应的确切产物，以及下一步的触发条件。下一版先读这些记录和当前 `git diff`，只重测受影响路径。新发现的通用故障模式补进本手册；具体一次性的数字、日志和进度留在对应审计或版本记录中。

这轮集中架构与体积审计是建立基线的工作，不是每个小版本的固定成本。只有媒体协议、存储格式、打包布局或长期磁盘行为发生相关变化，才重开相应深度审计。真实设备验收不能被手册或自动测试代替。
