## 后续：通知折叠与卡片堆叠

敲门冷却提示原先以标题、描述和颜色做完全匹配；描述中的秒数不同，会形成多张通知。现在冷却提示使用明确的 `knock-cooldown` 合并标识，只更新当前说明和重复次数，保留同一通知 ID。普通通知仍按完整内容合并，操作回调和持久性不同的通知不互相覆盖。

共用 `ToastRegion` 默认显示最新完整卡片，后方最多露出两层缩进卡片的细边和阴影。相同通知重复触发也会有堆叠深度；不同通知通过“展开 N 条通知”查看，保留各自的关闭和操作按钮。后方轮廓不接受点击、不包含可访问正文，不会把隐藏按钮留在 Tab 顺序里。只有一条且未重复时显示单卡，所有通知类型共用该布局。

通知队列仍最多保留 3 条，原成功／普通／警告／错误的显示期限不变。计时器按通知 ID 管理：合并时重新计时，关闭或被队列淘汰时取消计时，旧计时器不能提前删除更新后的提示。没有更改敲门频率、通知业务内容或用户数据。

验证：通知合并、不同操作隔离、队列边界、堆叠层数及页面／架构回归 41 项通过；全量 smoke 共 893 项，892 通过、1 跳过、0 失败。类型检查、定向 ESLint、格式检查、架构预算及普通 Renderer 构建通过。隔离 Electron 的实际组件覆盖 StrictMode、变化倒计时、混合通知折叠／展开、操作回调、关闭首张／最后一张、360px 窄窗口以及合并后的计时器续期和最终自动消失。使用 offscreen 渲染确保隐藏测试窗口的 Framer Motion 动画实际完成，再检查卡片边缘；没有操作真实房间或真实资料。报告、截图及一次性夹具归档在 `test-artifacts/toast-*`。本轮未发布。

1. **聊天区：** 消息列表底部增加 20px 渐隐，保留 24px 底部留白，滚动到最新消息时正文不会进入渐隐区。撤回按钮移出文档流，悬停或键盘焦点进入该行时显示；连续消息不再为撤回单独占据昵称行。触摸设备保持直接可见，原有撤回处理函数不变。

4. **角色清单：** 删除仅被测试引用的 `CharacterPackManifest`、渲染类型和静态清单，调整历史实施表的状态。实际角色渲染、资源和场景生命周期注册器继续保留。

## 后续：敲一下消息颜色统一

两条系统消息原本使用同一 CSS，但最新消息的 GSAP 淡入可能被 ACK 或其他消息更新中断；原来只调用 `timeline.kill()`，会遗留半透明的内联样式。改为有作用域的 GSAP context，在清理时 `revert()` 恢复原始样式。系统消息从出现时就保持完整透明度，并统一使用不透明浅色底和同一文字颜色，避免位置不同导致底色透出差异；保留轻微位移动画。

本轮类型检查、定向 ESLint、普通 Renderer 构建通过，没有新增或运行测试套件，没有发布。此前音效和连接验证仍属于各自原有记录，不作为本次视觉效果的实机证据。

## 后续：交互音效核查

| 交互                                      | 本轮处理                                                                                                                      |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 自己进入、退出、切换房间                  | 保留成功进入和主动离开的语义音效；进房音量保持原先较低值，避免与首段语音叠加                                                  |
| 朋友加入、离开                            | 改为同一房间内按账号／资料身份观察；空座位、初始快照、主动切房、临时 Peer ID 替换不产生进出提示；真正离线或移除发一次离开提示 |
| 门上暂离、回到工位                        | 本人和朋友均有轻柔提示；同次操作的自动静音不再额外叠一声，已静音时暂离也有反馈                                                |
| 麦克风、扬声器、设备选择                  | 保留状态反馈和设备切换反馈；扬声器开关引起的联动静音只播放扬声器提示                                                          |
| 屏幕分享                                  | 本人原有开始／停止提示保持；补上房间内朋友开始／停止分享提示，朋友退出时不另叠分享停止声                                      |
| 聊天、快捷语音／音乐、敲一下、收藏        | 保留已有发送／接收提示、音频包播放和两次门铃；快捷消息音量与用户绑定不变                                                      |
| 录音、标记、AI 任务、登录、复制、设置导航 | 保留现有开始／结束／成功／失败等语义音效                                                                                      |
| 普通按钮、原生开关、下拉框、滑块          | 语义音效优先；补原生控件完成操作的点击反馈，不在输入每一帧或打字、悬停时播放                                                  |

根因及维护边界：原常驻 Hook 比较临时 Peer ID，且缺少房间生命周期边界；现在独立音效观察器只读取已提交状态，按微任务合并联动更新，不修改连接、Track 或任何用户数据。重连稳定 3 秒后仅发恢复提示，退出、切房或卸载会取消待发提示。常驻组件不再因成员说话或连接统计刷新而跟着 React 重渲染，待发点击定时器也随卸载清理。

音效库按当前音色包异步预加载，原先播放时切包可能让预加载缓存落在错误的包。现在各包保持固定播放器并共享一个输出 AudioContext，缓存常用进出／暂离提示；全局最多保留 6 个活动播放，输出仍跟随用户选择的扬声器。没有提升现有总体音量。

验证：状态转换定向测试覆盖加入／退出、Peer 替换、离线占位、暂离／返回、切房、重连、持续失败、计时器销毁和分享结束。隔离 Electron 的实际 React Hook（StrictMode）验证 12 个交互结果，包含暂离无双响、本人退出无清理静音声、控件提交有声且打字和拖动过程无声；34 个合成提示均创建了非零 PCM 的真实 Web Audio 播放源，门铃 WAV 也成功解码为非零 PCM。报告在 `test-artifacts/ui-sound-review.json`。测试静音系统输出，没有访问真实客户端目录；这不代表真实耳机响度、实际朋友进出或远端听感已验收。类型检查、定向 ESLint、普通 Renderer 构建、架构预算检查通过；全量 smoke 共 889 项，888 通过、1 跳过、0 失败，日志在 `test-artifacts/ui-sound-smoke.log`。预览入口已移除，专用预览进程已停止。本轮未发布。
