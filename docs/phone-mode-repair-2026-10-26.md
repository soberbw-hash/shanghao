# 电话模式：游戏按键与松键延迟

本轮用户明确要求整个软件今后分发的新版本均默认管理员启动，覆盖此前普通权限启动的默认决策。当前没有发布新安装包。

## 已定位的两个独立问题

1. LOL 前台的权限高于原上号输入监听进程。用户确认管理员运行后，桌面与无边框游戏中的 F2 都能触发。已配置本机正式版兼容性启动标记、开发版稳定入口的条件提权，以及后续 Windows 安装包的 `requireAdministrator` 清单与校验。仍由 Windows 正常显示 UAC，不绕过系统授权。
2. 用户按住两秒松开后仍延迟约五六秒。新增有界状态日志证明松键意图及时到达，确认恢复分别等待 4835、2005、3324 毫秒。独立原生测量发现第一个渲染端点的 `SetMute(true)` 约 5019 毫秒后返回 `0x800703e3`；恢复请求本身只需几毫秒。延迟不是简单换按键能够解决。

另修复 Raw Input 遗漏释放后永远保留按下值的问题：仅在可访问且不跨高权限的桌面，用连续 40ms 的物理状态校正；安全桌面和拒绝读取不会被解释为松键。保留原有隐私门控、原生恢复确认与失败时保持静音。

## 输出声音改用会话静音

- 渲染端点使用 Windows 音频会话静音，避免调用会阻塞的 USB 硬件静音和音量写入；麦克风继续使用系统捕获端点静音。
- 逐会话先将原静音状态写入恢复记录，再修改与回读确认。监听注册在枚举前；新应用声音会触发同一串行队列处理，不在 COM 回调中直接修改音频。
- 恢复仅匹配原会话实例，不能把旧应用的状态套到新实例；已结束的实例不重建。旧格式端点恢复记录继续可读。所有音量数值保持不变。
- 明确退出恢复，意外管道中断继续保持静音；重新启动的恢复检查保留。

## 当前证据

- 原生按键状态 21 项通过，真实 Raw Input 注册、桌面与权限状态只读检查通过。
- 新输出通道连续 20 次真实启停通过：三个输入、两个输出，静音确认、音量不变、准确恢复、异常退出保持静音及重新启动恢复均通过，开启最慢 115ms。
- 一次独立测量中，静音约 132ms 完成，释放请求约 13ms 完成。
- 已额外创建新应用的 Windows 音频会话，用纯静音 WAV 验证该会话被记录并静音，退出后原状态恢复。
- 已授权重开开发版，新音频助手的文件哈希与通过检查的候选一致。用户最终确认“这次两边都能立即恢复”；对应真实操作的释放确认耗时为 14、13、17ms。第一次输入修复没有解决五秒延迟，最终会话静音通道才通过这项实机验收。
- 最终完整 smoke 1493 通过、5 跳过、0 失败；类型、相关 ESLint、架构检查通过。五人音频／媒体自动化此前通过，原生输出会话修改另有上述真实 Windows 检查。新安装包尚未生成，不能宣称所有已安装旧版已更新。

## 保留待续

屏幕分享“能见卡片但黑屏／一直连接”仍未修复完成。用户指定的项目已确认为 [Piik](https://github.com/TNTcraftHIM/Piik)；历史版本只参考选择器界面，没有集成其媒体底层。已发现现有路径把 `live && enabled` 当作视频可用，而界面还要求 `!muted`，可能提前关闭备用画面。下一步需要失败用例与实际首帧证明，对照 Piik 的首帧后提交和保留可用路径机制实施；目前不得声称已完成集成。
