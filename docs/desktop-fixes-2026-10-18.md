# 上号开发版修复记录（2026-10-18）

本轮基于本地 v3.4.9 继续修复，不重置账号、设置、录音、聊天、已下载模型或已有转录。原始诊断包只读分析；下文不包含凭据、聊天正文或录音内容。

## AI 提问与真实接口

- 回答提交后使用欢迎卡片全宽；大 Bot 缩为标题旁的小头像，输入框位于回答之后。初次“开始提问”仍在原位置由 112 px 展开，保持原有欢迎布局。
- 成功后清空输入，不重复显示同一个问题；历史默认折叠，回答区域有独立滚动上限。移除旧浮窗样式对内嵌区域的背景、阴影和模糊覆盖，修复 HarmonyOS 字体的资源引用。
- 关闭期间保留输入/回答布局直到收起完成；组件卸载或切换房间时取消在途请求，拒绝迟到结果。
- “你能做什么”等明确功能介绍问题返回应用自身的真实能力说明，不让模型猜测系统权限；普通问题仍使用真实文本请求。保留房间云端原有检索路径，不声称自定义 API 已经联网核实版本。
- 用户提供的 GLM 官方密钥分别保存于正式版/开发版的加密配置，并备份在桌面私人资料目录。完整 `AiVoiceMemoryService.askMemory → AiTextGateway → CustomAiProviderStore` 调用实测返回正确结果；没有使用用户语音或历史聊天。
- SenseVoice 充值后的完整转录请求返回 HTTP 200、ready、storage，并生成非空转录。只上传合成测试语音，详见 [云转录记录](cloud-transcription-debug-2026-10-18.md)。

## 成员显示、离开与持续状态

- 角色根节点默认可见，动画丢失时不再回落到透明底态；保留原有走路、座位、重连去重及路线恢复机制。
- 本地离开意图和返回意图均不被迟到的相反位置回执覆盖；服务端仍可在正常座位之间解决占位冲突。
- 聊天标题空白处加入“离开、吃饭、厕所、回来”，整体向左留出额外 8px。三个状态均保持原座位，只静音并在头顶持续显示状态；点击“回来”清除状态并恢复之前的麦克风选择。明确状态期间闲置检测不再把角色自动移到门口；原有点击门口的离开功能保留。
- 通过已有房间控制消息传送有限枚举状态；正式中继可兼容转发。成员快照保留状态，后加入/重连时重新同步，离房时清理。旧客户端仍能看到静音，需要更新客户端才会显示新的状态标签。
- 房间状态的稳定引用比较包含新字段，避免状态已收到却被渲染缓存忽略；返回沿用之前的静音选择并尊重关闭扬声器/电话模式约束。

## 分享与语音恢复

- 分享开始/停止串行执行；旧视频轨道结束回调在执行时核对归属，不能关闭下一次分享。房间清理使尚未执行的分享失效。
- 一个成员拒绝视频轨道时只恢复该成员，不让其余已连接成员一同失败。
- 停止系统音频分享后，将健康发送端和 Relay 切回麦克风；单个失败成员进入定向恢复，不把健康成员回滚到即将关闭的混音轨道。正常切换输入设备仍保留原有完整回滚保护。
- 房间退出时，即使麦克风恢复失败，也释放混音图和捕获资源。清理已离开成员的 Relay 状态，消除旧 peer 残留。
- 放大窗口的可选编码参数失败不会中止正常协商；远端视频流改变或从图片后备路径恢复时重新绑定发布器，迟到旧会话不能关闭新窗口。
- 放大观看端在新的发布器握手时重建对应接收连接，不把新发布器的媒体身份写入旧连接；异步处理核对当前接收器，避免换轨后永远加载或旧画面闪回。实际视频测试同时验证首次观看及替换发布器后的连续解码。

## 后台电话快捷键

- 增加独立的 Windows Raw Input 消息窗口（INPUTSINK），保留物理采样与原有钩子路径。不拦截游戏输入、不注入游戏、不提升应用权限、不记录文字。
- 只有真正被接受的钩子按下/释放才推进事件优先级；被拒绝或重复的钩子不能压掉独立物理输入。
- 原生进程实测 ready、rawInput 均为 true，退出正常；诊断增加独立的原生/原始输入可用布尔值。
