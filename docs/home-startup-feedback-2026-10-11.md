# 首页卡顿与音效叠播 · 2026-10-11

## 用户反馈与定位边界

用户明确说明发生在刚显示带“进入上次房间”按钮的首页，而不是点击之后的房间场景。当前运行的是先前的本地图标候选包；本轮没有退出房间、重启用户程序或修改音频设备。

源码检查确认：房间模块在 App 模块加载时立即导入；bootstrap ready 后角色图集开始解码，场景／设置页另一路预加载与首页动画并行。首次 pointerdown 和 keydown 分别触发音效准备，多个音效 pack 同时合成，且共用 AudioContext 的每个播放器都再次切换输出。UISFX 在 suspended context 中会创建并调度音源，恢复时可一起释放。现有日志未记录逐个提示音或首页帧时间，不能认定每项都已在本机复现，也不把正常素材的多个音符当作已证明的多个播放器。

## 本地修改

- 房间模块改为按需缓存导入；首页稳定并让过渡完成后，按空闲窗口依次准备房间模块、场景、角色与设置页。图片之间让出线程；隐藏／失焦暂停可选准备，取消会清理调度及监听。真实进房直接加载所需模块，不等待这条可选准备队列。
- 界面音效在启动数据稳定前关闭，房间反馈订阅以稳定状态建立基线，初次读取旧 Failed 状态不播放失败提示。
- 手势只解锁音频，不在首次输入上启动整批素材合成；音效准备改为分批、可取消的空闲任务。
- 共用输出的切换串行并按已成功路由的设备去重，不因新 pack 再打开相同输出。
- suspended context 不再提前调度声音：只保留最近一条提示，恢复超过 250 ms 或启动代际改变则丢弃。合成界面提示最多同时两条，真实敲门、语音包／音乐和通话沿用其原播放器与独立音量。

未修改 WebRTC、麦克风获取、录音或信令调度；不删除用户数据，不修改系统音量或降低用户配置的音效音量。

## 检查与交付边界

Desktop 类型、相关 ESLint、Renderer 生产构建和 diff 空白检查通过，架构预算文件没有提高，场景预热模块保持原有行数上限。既有 room-layout 源码断言同步为缓存按需导入；本轮未新增或运行测试套件。真实首页过渡与听感尚待包含这批修改的程序验证，现有 IconFix 包没有自动更新。本轮没有打包 EXE、递增版本或发布。
