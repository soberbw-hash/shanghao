# 房间实时聊天纪事设计

状态（2026-10-31）：实时纪事已在本地接通客户端采集、信令、服务端识别／汇总及界面；尚未部署，也未通过真实供应商及多台设备验收。语音回溯仍只有基础模块，尚未接入房间与存储。两者不改变本地录音和录音库的处理。

## 本地实现与验证边界

`RoomChronicleClient` 通过 JoinAck 的显式能力声明兼容旧服务器；个人语音只在本人主动参与后使用现有静音门后的 Track 编码。当前每段 30 秒，服务器收齐已到达的识别结果后等待约 15 秒合并总结；实际可见延迟还包含网络与供应商处理，不声称逐字实时。切换聊天不卸载采集，主窗口后台计时不节流，视觉暂停仍由原有可见性规则控制。

`RoomChronicleProcessor` 对独立成员的音频分别识别，姓名取信令已认证的成员资料。音频不落盘，接受队列／并发受限；摘要重试复用已识别文字。房间成员变化、撤回和结束会取消任务并检查代际，房间清空后清除会话。最多保留最近 60 条短纪事；这不是持久聊天档案，也不包含语音回溯授权。

本地 WebSocket、服务端处理与撤回／重试夹具通过；独立 Electron 以合成音频实际完成 30 秒编码、聊天切换、隐藏窗口续跑及停止后的通话 Track 保留。文本供应商使用夹具，不代表真实云端结果。当前未上线；旧服务器仅显示尚未支持，不尝试未知协议。

## 界面

- 右侧顶部使用「聊天」「转录」两个页签，快捷消息和状态按钮始终保留；仅下方消息区域切换。转录页首次显示「开始记录」和一行清晰说明，开始后默认显示带时间的阶段总结、具体事件与一两句有分寸的助手点评，按需展开识别原文。支持回到聊天，并保留各自滚动位置。
- 使用轻微横向位移与淡入淡出，窗口缩小、低性能或系统要求减少动态效果时降级为无动画。动画只作用于面板，不重建或暂停语音和录音链路。
- 普通内容用可读短段落，吐槽必须根据实际对话，不编造事件或冒充成员说过的话；识别不确定时省略结论。时间标签注明纪事中的时间，不假称逐字精确定位。

## 房间共享与生命周期

- 初始关闭。第一个成员点击开始后，服务器原子创建当前房间的唯一会话；多人同时点击只得到同一个会话。房间醒目显示正在进行云端语音处理，每个人可停止发送自己的音频，并在新成员加入时告知。停止参与不影响通话。
- 成员各自按授权状态提供自己的音频短段，服务器按房间和会话校验身份、去重、排队并转录，再把结果汇总给当前房间；音轨身份来自已验证的房间成员，不靠模型猜测，也不把混音冒充独立音轨。该链路独立于本地录音文件，不改变录音是否开启。
- 其他成员打开页签时订阅现有会话，先获得允许范围内的近期纪事，再接收增量；不因切页或无人打开而自动启动或重复识别。会话持续到房间结束或被有权成员停止，服务重启与断网时展示真实状态并恢复或明确结束，不能假装还在处理。
- 建议仅向有权限的当前房间成员提供会话内容；音频短段处理后删除，文字仅作有限时间的会话缓存，具体保留时间和停止权限在产品设置中明确告知。既有私人房间的房间身份与访问校验继续适用；临时联机需要单独处理身份认证，不可直接沿用私人房间假设。

## 实现方式与约束

首选复用服务器提供的 SenseVoice 云端分段识别，客户端按成员发送经授权的短音频段，服务端按房间合并文字并定期调用文字模型生成纪事。每隔数分钟汇总不要求逐字流式 ASR；音频仍应在语音停顿附近切成较短片段并限制大小，避免长请求超时和遗漏。停顿边界、处理速度、成本以及重试去重必须实测，不能把预测当作已验证性能。上传失败保留有界队列并明确提示，不能无限累积音频。

本地优先候选为现有 Qwen3-ASR-0.6B；需要更精确定位时再使用独立的 Qwen3-ForcedAligner。两者不会自动识别真实姓名，成员身份须来自可靠的独立音轨。它会占用用户设备资源，应作为可选方案，并在游戏负载下实测。Paraformer 可作为轻量备选；最终模型选择以房间音频的实测效果为准。当前实时纪事仅接云端服务，本地模型还未接入此路径。

建议采用客户端采集与切段、服务器统一编排及调用云端模型。当前服务端语音 API 是上传音频文件并返回文本的接口，不是已验证的流式识别：首版可在讲话间隙或短窗口分段，预计存在数秒至数十秒延迟，实际延迟、额度和成本需实测后确定。服务器端按房间限并发、限速和队列上限，语音与实时通话优先；不能对每次观看分别上传或重复生成。

摘要用云端文字模型按一段对话批量生成，而不是每句话都调用；初始设计为约 30–60 秒汇总一次，有足够有效内容才生成，安静时不生成，实际间隔根据延迟和费用测试调整。每个条目绑定输入片段范围、稳定 ID 与版本，避免重复、错序与断线重放。低置信度、音轨缺失、重叠讲话或处理失败要明示，不把推测说成事实。房间隔离、令牌校验、速率限制、成员退出与重进、会话结束和故障恢复必须经过服务端验证。

录音库已有面向已保存录音的独立音轨及分段转录流程；实时纪事使用另建的个人采集、服务端会话及订阅协议。房间隔离、并发界限、取消、授权变化和旧服务器降级已有夹具；实际 API 成本、弱网、多台真实设备和长时间稳定性仍待验收。

## 语音回溯与纪事结合

语音回溯默认关闭，与实时纪事是两个独立开关。首次开启回溯必须获得当前房间所有成员的明确同意；成员加入、退出、撤回授权或房间切换时立即停用并清空未保存缓冲，新成员加入后须对新的成员集合重新授权。每位成员可撤回，房间内持续显示缓冲状态；成员未授权时不得偷偷采集或保存。与纪事的单人停止提供音频机制分开，开启纪事不代表同意回溯。

同意后本机把经处理的麦克风和实际房间播放混音放进最多 60 秒的内存环形缓冲。快捷键只快照选择的 15、30 或 60 秒（默认 30 秒），后台保存到本地片段库；从开始缓冲至今不足所选时长时只保存实际已缓冲部分。未保存的音频不写盘、不上传、不跨房间复用；保存的片段也不会自动上传或分享。保存后可回听、重命名、裁剪、删除与导出；二次加入音效板前要确认相关成员许可。

可以从某条纪事主动保存对应的仍在缓冲区内的语音；不能把已过期的内容假装补录，也不能由 AI 擅自保存或上传音频。实时纪事不因回溯启停而改变；已产生的文字不能替代或证明音频仍可回溯。纪事转录结果可以按真实时间段复用给已保存片段，但缺失或不确定时要明确标注，不能虚构。

现有 `createMixedCallStream` 能输出麦克风与房间音频混合流，且有成员轨道逻辑，但其生命周期和落盘行为绑定正式录音；`RemoteAudioMixer` 还有远端播放输出 tap。回溯需独立、低开销的只读音频采集节点与专用生命周期，不直接启动正式录音。需验证本地麦克风开关、耳机／扬声器音量、扬声器关闭、播放源替换、声道与时间同步、后台快照及混音避免重复；缓冲、授权状态必须以房间和成员代际隔离。当前仅有独立的内存缓冲和授权状态基础代码，尚未接入房间、快捷键或存储，也尚未完成跨客户端授权协议。
