# 房间邀请、AI 界面与官方图标

## 本地修改

- 编辑房间的频道号改为标题下的固定信息，创建时仍保留输入和随机生成；名称、图标和保存逻辑保留。
- 邀请文本包含房间名、六位频道号和官网 `/join` 入口。页面提供打开上号、复制频道号和下载；原生 `shanghao://join` 带明确加入动作。浏览器可能要求点击确认打开应用，未安装时不会假装已加入。
- 全局接收邀请等待启动和登录完成；房间元数据按永久 RoomID 查询，频道号不用于重定向。已在目标房间时不重复连接；跨房使用现有切换流程，正在录音时保留结束录音确认。旧链接与托盘提醒仍仅打开房间预览。
- 邀请携带当前服务器地址，避免另一台服务器的设置导致房间查找失败；共享地址不接受账号、密码或查询参数。在现有通话中收到不同服务器的邀请时先提示退出，不在后台改掉正在使用的服务器。
- 官网当前首页是静态 `index.html`，邀请使用独立 Vite 多入口 `join.html` 和 `dist/join/index.html`，没有替换首页。首页两处旧 SVG 品牌标识已改为官方 PNG。
- AI 三张用户原图保留在仓库；按用户最新要求，所有 AI 位置统一使用耳机机器人的透明抠图，去掉原图方形底板和按钮底框，不再按状态换成其他图案。删除示例提问；等待状态统一为“正在回答”，不根据经过的秒数假称已完成搜索或整理。
- 答案只在用户点击“发送到聊天”后发送；沿用当前 500 UTF-16 字符上限和 ACK/失败重试。长答案按 Unicode 字符分段，顺序发送，失败保留客户端消息 ID 和已完成进度；再次点击不重复发送已确认部分。切房或断线中止后续发送，不自动公开本地记录或录音来源路径。
- 新错误提示分别说明认证、余额、未配置、限流、超时、断线和回答格式异常；输入空答案不再被记作成功。输入法确认文字时不触发提问。

## AI 不可用核查

2026-10-01 经现有 SSH 访问做只读配置核对和官方余额查询，密钥始终留在服务器，不输出、不复制到本机。余额接口 HTTP 200，`is_available=true`，查询时总余额 **7.81 CNY**。两个极小的合成问题经当前 Anthropic 兼容入口返回 HTTP 200；出装查询约 **5.8 秒**，返回包含搜索工具结果的完整 JSON 答案，`stop_reason=end_turn`。服务器已有两条当天正常问答完成记录。

这些证据证明检查时 API 与联网路径正常，**没有复现用户此前客户端失败，不能据此说它已经定位并修复**。未登录真实用户、未加入真实房间、未上传用户语音记忆、未充值或修改服务器配置。若开发版再出现失败，应按新增的具体错误提示定位客户端会话或返回格式，不能再次笼统解释为没费用。

官方余额接口说明：[DeepSeek 查询余额](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)。余额会随调用变化，本文不是实时余额表。

## 图标与发布边界

官方主图已原样导入并保存校验记录，见 [图标规范](branding/README.md)。本机上号外部图标和快捷方式已有可回退备份，EXE 内嵌图标需正式安装版本更新；Windows 固定项可能仍需重新固定。

本轮类型检查、定向 ESLint、共享包/客户端/官网普通构建通过。没有运行额外测试套件、打包 EXE、修改版本号、推送或部署。网页邀请入口必须随官网部署，自动加入必须随新客户端发布；本地实现不能代表现有线上链接已生效。真实浏览器唤起、登录后入房和朋友看到 AI 分享待对应版本实际使用确认。
