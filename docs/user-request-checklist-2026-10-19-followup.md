## 通知、电话模式与天气的现场证据

- Windows 通知故障已复现到系统层：上号保存的通知选项为开启，`Notification.isSupported()` 为真，Electron 先发出 `show`，随后发出 `failed`，错误为 `0x803E0114`（系统设置禁止投递）。WinRT `ToastNotifier.Setting` 返回 `DisabledForUser`，系统通知总开关实际关闭。
- 改动前已把原 `HKCU\Software\Microsoft\Windows\CurrentVersion\PushNotifications` 精确导出到 `%TEMP%\shanghao-notifications-backup-20261019-083030.reg`，原 `ToastEnabled` 为 DWORD `0`。仅改注册表为 `1` 时，运行中的系统仍拒绝通知；随后通过 Windows 设置页面开启了顶部的通知总开关，WinRT 返回 `Enabled`，隔离 profile 的原生探针等待两秒后返回 `shown-without-native-rejection`，退出码为 `0`。未重启 Explorer 或通知服务。
- 开启总开关后，设置页面显示勿扰模式仍为开启；本轮没有改动勿扰或其他通知选项。因此上述结果证明原生投递不再被系统拒绝，不代表已目视确认弹出横幅，也不等同于真实第二台客户端消息和上线通知的端到端验收。新增原生失败监听、一次性界面提示和“打开通知设置”入口，避免以后再次静默失败；日志只保存失败分类。
- 电话模式使用柔和的短双音，跟随界面音量。助手就绪后才提示进入，先同步关闭上号当前发送音轨，再播放约 162 毫秒的短音，180 毫秒后执行系统静音；等待后再次检查请求代际，快速松开不会迟到激活。只有原生确认后才显示“电话模式已开启”，设备重校验不重复提示。未短暂恢复任何系统端点或其他应用音频；未增加退出音。
- 天气移除了精确定位行、开发预览选择器及全局预览状态。新配置和缺失字段默认尝试 Windows 定位，定位失败使用现有网络定位回退；旧配置中显式关闭系统位置的选择仍保留，手选城市仍可用。组件的独立测试预览参数只供资源审阅夹具使用，正常房间持续显示真实天气。
- 最新定向验证：通知生命周期、电话快速按放/失败/门控顺序/重复提示、天气和架构护栏合计 41 项通过；设置迁移与天气此前 44 项通过。真实设备的电话提示音听感，以及真实好友消息横幅，仍需单独验收。
