# 换座步行动画平滑处理

## 根因与修改

- 原步行条带只有 16 个姿势，旧播放约为 50 个姿势/秒；提高切帧速度不会增加姿势信息。改为两个交替的纹理层：仅在层完全透明时换姿势，透明度在相邻姿势间连续融合。`transform` 与 `opacity` 由 Web Animations 控制，沿用现有 Chromium 动画系统，不增加逐帧 React 更新、Canvas 绘制或独立 rAF 循环。
- 两层使用同一个时间原点；隔离的 `plus-lighter` 混合避免交叉淡化时身体亮度闪烁。走路节奏沿用路线速度与动物个性的 `strideDurationMs`，不再冻结首次渲染时估算的刷新率。高刷新率屏幕可以绘制更多过渡画面，但这不等于有 120 个独立的原始姿势，也不保证实际机器达到 120 FPS。
- 五张未修改的 4096 × 256 条带按每格 256 px、alpha > 160 测量顶部位置。狐狸原素材顶部在 10–28 px 间变化；按各动物的中位位置补偿 75%，保留少量自然起伏。测量值位于 `useWalkingCycleMotion.ts`；换素材时必须重新测量，不能沿用旧值。
- 删除换座前 72 ms 的等待及对应 240 ms 起身效果，避免中途切断造成上跳。坐姿与步行姿势仍通过原有透明度过渡交接。
- 移动期间停止随语音音量缩放整个身体；阴影维持稳定形状。移动姿势临时停用灰度滤镜，没有添加持续模糊或大面积残影。
- 只有步行且资源就绪时创建动画。窗口隐藏/失焦暂停，恢复时继续；换头像、换节奏、停止步行及卸载时取消旧动画、退订可见性。支持减少动态效果模式。语音、录音、连接和座位事实状态不随视觉暂停。

参考：[MDN plus-lighter 交叉淡化](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/mix-blend-mode)、[Chromium 合成动画](https://developer.chrome.com/blog/hardware-accelerated-animations)。
