# ShangHao v3.0.7 交互丝滑度专项报告

日期：2026-08-29

## 结论

本轮没有删除房间角色动画、页面过渡、阴影、模糊或品牌视觉。优化重点是把会阻塞首帧的工作移出点击关键路径、停止隐藏页面的后台重活，并对确实值得保留的页面做有上限的缓存。

## 优化前后的关键路径

| 场景              | 优化前                                                             | 优化后                                                                                         |
| ----------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| 进入房间          | 清理旧会话、读取聊天记录并完成信令连接后才切到房间                 | 点击后立即绘制房间壳层；历史记录读取与信令并行；连接失败再安全返回首页                         |
| 设置页开关        | 每次退出设置都会卸载整页；进入后又在空闲任务里依次预挂载全部重页面 | 设置壳层首次打开后保留；只缓存最近访问的 4 个栏目；隐藏时暂停诊断、录音库、AI 状态和麦克风测试 |
| 设置栏目切换      | 重页面可能反复初始化，后台预热还会与用户操作争用主线程             | 已访问栏目直接显示；重工作只在栏目可见时运行；切换继续使用原有过渡                             |
| AI 模型页         | 每 2 秒扫描全部模型目录并逐模型推送状态，整张长页面参与位移动画    | 可见后空闲时只检查一次；状态批量推送；AI/录音库重页面不再做整页 GPU 位移                       |
| 聊天图片放大      | 等待原图 `decode()` 完成后才显示灯箱，容易出现点击无反馈和白色闪块 | 下一帧先显示背景与控件；图片解码并行；悬停/按下时预解码，最多缓存 12 张                        |
| 麦克风/扬声器菜单 | 每次打开都重新挂载菜单及其内部状态                                 | 只保留用户实际打开过的菜单，后续开关复用 DOM；未打开的菜单不占用缓存                           |
| 长录音模型对比    | 固定 10 分钟看门狗会把慢模型加载/推理误判为无进展并暂停            | 看门狗随真实持久化心跳续期；连续 30 分钟没有心跳才触发保护性暂停                               |

## 开发性能监控

开发版新增了可关闭的性能 HUD，不进入正式安装包的普通界面。按 `Ctrl+Shift+Alt+P` 开关，可观察：

- 实际 FPS、帧时间 p95/p99、长任务和长帧数量；
- DOM 节点数、可用时的 JS Heap；
- 设置页和 AI 模型页的渲染次数；
- 点击开始、视觉反馈、路由切换、首帧、可交互、后台初始化完成六个阶段。

监控数据有明确上限：最近 80 次交互。图片预解码缓存最多 12 张，设置栏目缓存最多 4 个，避免“为了快而无限吃内存”。开发者工具中也可以调用 `window.__shanghaoPerformance.snapshot()` 获取当前快照。

## 验证结果

- Prettier 格式检查：通过。
- ESLint：通过，零 warning。
- TypeScript 全工作区检查：通过。
- Electron 主进程与 Vite Renderer 生产构建：通过。
- AI 页面专项性能保护测试：3/3 通过。
- Voice Memory 回归：除同文件中一条既有房间顺序断言外，本轮相关用例通过。
- 自动化测试覆盖了设置缓存边界、隐藏后台任务、房间首帧顺序、图片解码不阻塞以及音频菜单复用。
- 自动化测试覆盖了模型对比看门狗的心跳续期和慢推理阈值。

## 数字说明

自动性能捕获使用独立测试数据目录。当前目录没有真实账号会话，自动脚本停在登录页，因此那次采集不能代表设置页或房间页，本报告没有使用也没有伪造那组 FPS/延迟数字。

在已登录的开发版里打开 HUD 后，建议分别连续操作 20 次以下场景，再导出快照作为机器上的有效前后数据：

1. 首页进入房间、退出房间；
2. 账号、通用、语音、快捷消息、录音库、AI 功能间往返；
3. 首次与再次打开麦克风/扬声器菜单；
4. 首次与再次打开同一张聊天图片，并切换相邻图片。

## 风险与人工验收边界

- 房间现在会先显示“正在进入”的真实状态；网络失败时返回首页，不会伪装已成功进入。
- 设置页保留的是有上限的最近访问栏目，不是把所有页面永久挂在内存中。
- 自动测试不能替代真实账号、真实房间、不同刷新率显示器和游戏前台下的手感验证；这些需要在已登录开发版上完成。
