# v3.3.0 底层收口复核（2026-09-30）

本记录以本地工作区为基线，保留原有未提交修改。只运行普通构建和隔离测试；没有打包安装器、发布、部署或操作真实用户资料。更早的架构与体积调查见 [架构进度](architecture-stability-progress-2026-09-27.md)、[体积审计](package-size-audit-2026-09-27.md) 和 [开发手册](development-playbook.md)。

## 本轮处理

1. **房间成员状态：**房间快照会按当前成员集合清理 Peer、ICE 候选、WebRTC 连通/音频/流动/卡顿证据、Relay 请求、屏幕分享及呈现回调。离开的成员即使尚未建成 Peer，也会释放已缓存的状态。Relay 目标筛选留在独立音频路径策略中；没有改写 WebRTC、DeepFilter、VAD 或采集链路。
2. **长任务：**同一 Runtime 资源的跨进程锁现在有有界等待，并能回收在争锁清理阶段死亡的进程留下的锁。等待超时会明确失败，成品仍须校验；未使用真实用户模型作为夹具。
3. **IPC 数据边界：**录音 Marker 写入移到专门模块，只接受当前录音目录下实际存在的 M4A，限制数量和时间偏移，并原子提交文本。AI 语音记忆处理请求先验证对象结构、时间线和序列化大小，再校验录音文件路径。主进程入口仅注册处理器。
4. **屏幕捕获发布门禁：**Windows CI 与 Release 在打包前运行 Electron 捕获测试，覆盖开始、停止、多档分辨率和回退配置；Track 未正确结束会失败。这是本机捕获门禁，不能证明远端 Viewer、系统音频与真实多人分享。
5. **收藏提示：**其他成员新增收藏时出现红点，打开收藏后消失；已读时间按一号房/二号房分别保存。新收藏附带稳定成员身份，避免自己重进房间后因为 Peer ID 变化而误判；旧收藏继续按原格式读取。首次升级会建立已有内容基线，不把旧内容当新消息。
6. **代码护栏：**新增的房间成员清理、录音 IPC 校验模块均纳入架构测试。IPC 录音职责和录音标题 CSS 从原入口拆出，原有核心入口上限未上调。

## 已复核但暂不改动的边界

- **权限：**安装清单仍要求管理员。防火墙写规则与 Windows 外观操作需要系统级写入，游戏探测、音频、网络和普通录音原则上不需要。直接降权会改变现有安装和更新行为；按 [管理员权限审计](windows-admin-privilege-audit-v3.2.0.md) 先在隔离普通账户验证，再设计只承载固定高权限命令的 helper。
- **体积：**2026-09-29 的 [v3.3.0 候选包报告](package-size-candidate-v3.3.0.json)记录安装包 171,644,698 字节、解压后 487,021,577 字节，其中 Electron 运行时约 325.8 MB、单份 FFmpeg 约 82.8 MB、DeepFilter 约 17.6 MB。这是此前候选包快照，不是本轮代码的安装包实测。FFmpeg 承担录音编码、探测与 ASR 解码，不能只按当前输出编码裁剪输入解码器；本轮不替换二进制。
- **自动更新：**后台下载与用户点击安装的边界保持不变。N-1 数据夹具能检查存储兼容性，不能证明旧正式版安装程序实际完成“发现、下载、点击安装、重启、资料保留”。此链路仍需隔离 Windows 配置和用户点击。
- **长时间性能：**本轮普通构建、快速测试和短时 Electron 捕获均未测得数小时挂机的 CPU/GPU/内存曲线；因此不宣称长期无泄漏。真实五台设备及手机麦克风远端听感也未由自动化替代。
