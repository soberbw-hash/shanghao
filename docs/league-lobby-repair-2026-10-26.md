# 英雄联盟房间人数读取修复 · 2026-10-26

用户创建了单人房间，上号仍只显示“英雄联盟”。只读实机检查发现：管理员权限下可以查询 LeagueClientUx，但 Windows PowerShell 默认以系统代码页输出；中文安装目录让 JSON 转义损坏，连接信息解析失败。原实现安全降级到游戏进程检测，因此训练模式的实时接口可用，而客户端房间详情始终缺失。

## 本轮修改

- 客户端信息查询明确使用 UTF-8，保留原来的进程 PID 绑定、固定本机接口、只读、超时、大小限制和关闭检测后的代际保护。不保存或输出本机接口凭据。
- 房间状态显示模式和实际人数；排队、等待确认也读取当次真实人数，不沿用旧局或旧房间的缓存人数。
- 已识别当前国服 `KIWI` / queue 2400，兼容现有线上信令的“大乱斗”模式值。暂不新增旧服务器无法识别的模式枚举；精确“海克斯大乱斗”名称仍需后续客户端/服务端兼容升级。
- 只有真实人数与容量均有效时，显示等待队友/正在匹配的席位画面。未知人数、选英雄或进入对局时使用原游戏画面；底部“英雄联盟”名称和标识保持原样。

## 证据与边界

实机只读结果：`phase=lobby`，`partySize=1`，`partyCapacity=5`，`gameMode=KIWI`，`queueId=2400`。没有读取后修改游戏，也没有记录玩家身份或连接凭据。

中文目录 PowerShell 往返、房间解析/时钟/取消竞态、本机 TLS、真实信令晚加入、图像条件及相关房间布局共 51 项定向测试通过。隔离 Electron 页面验证 1/5 → 2/5、排队、进入对局的画面切换，以及英雄联盟角标保留；截图在 `artifacts/league-lobby-preview.png`。桌面类型、相关 lint、架构预算通过。

整轮桌面 smoke 共 1501 项，1494 通过、5 跳过，2 项指出新增等待房间样式挤入了已有 CSS 的冻结预算。已经把这项新职责放到独立 `217-league-lobby.css` 并给出明确预算，原有预算不增加；失败涉及的 5 项架构检查随后全部通过。五人 20 条定向音频回退路径、隔离 Electron 媒体恢复及 renderer 构建也通过。没有在修正 CSS 归属后再重复运行全部 1501 项。

按用户明确授权重开了开发版。实际游戏的双人加入、排队到开局、朋友电脑上的状态展示仍需后续实机观察；模拟数据的转换验证不能代替这些设备场景。本轮没有修改版本号、打包、发布或部署服务器。
