## 检查后沿用的现有实现

- 设置中心已有轻量 section 常驻、重页面只保留状态/数据的分级缓存；没有 `MAX_CACHED_SETTINGS_SECTIONS = 4` 的统一上限，也未在顶层订阅完整 settings 对象，因此本轮不重复改写。
- 聊天面板已有近底部滚动 ref；消息添加已有顺序追加快路径；网络健康已有可见值比较与原始 telemetry 分离。没有为了“重构”再改这些稳定路径。
- 主进程已有窗口创建后延迟初始化 AI 模型与 Voice Memory 的启动顺序。未在缺少冷启动前后数据的情况下调整登录、音频或初始化时序。
- 设置页现有进入动画不是每次切 section 都执行的横向位移动画；没有叠加新动画。

## 尚不能宣称通过的验收

- 真实 Electron 房间截图及 50 次以上设置来回切换测量未取得有效数据。独立测试账户在正式信令地址被以 `account_required` 拒绝；不能把此失败计入产品功能故障，也不能冒充已完成实测。
- React render 次数、commit time、long task、DOM 节点、JS heap、FPS、冷启动耗时目前缺乏同环境的前后基线，故不编造改善百分比。
- 连续 2–4 小时、多台真实设备、实际麦克风与扬声器切换、实体屏幕共享、签名安装包与自动更新完整回归未执行。五人自动化只覆盖模拟链路，不能替代这些实测。
- 没有证据表明发现新的 listener、timer 或内存泄漏；本轮只移除了已确认的无关订阅，不能据此保证长时间运行完全无泄漏。
- 独立 Electron 44 迁移分支、React 升级、AI 大文件拆分未开展；这次没有把未证明收益的高风险底层改动带进当前版本。
