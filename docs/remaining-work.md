# 上号剩余工作清单

这份清单对应 2026-09-27 的架构治理与体积审计需求，供后续接续工作；它不是每版都要重做的发布清单。已完成的具体实现与测试以 [架构稳定性进度](architecture-stability-progress-2026-09-27.md) 和 [体积审计](package-size-audit-2026-09-27.md) 为准，开始下一阶段前先核对实时 Git 状态和代码。

2026-09-30 的 v3.3.0 本地底层复核、修改与自动化结果见 [本轮收口记录](v3.3.0-system-hardening-2026-09-30.md)。屏幕捕获门禁已加入 Windows CI 和 Release；真实 Viewer、系统音频、旧客户端完整升级及数小时挂机仍按下文单独验收。

上述修复已随 v3.3.1 正式发布，安装包、更新元数据、GitHub 工作流、15 分钟耐久检查及 CloudBase 官网核对见 [发布记录](release-verification-v3.3.1.md)。此记录不关闭下方真实环境验收项。

## 当前剩余的验证与发布时复核

1. **资源所有权与任务生命周期：**FFmpeg 媒体探测、可选 Runtime 下载、模型 Runtime 准备、FreeToken 大小探测与重试等待已传递取消；后来的 FreeToken 准备调用者可独立取消等待。流式录音重复完成请求、恢复清单、分轨录音冲突及启动迁移登记器已加所有权或数据保护。隔离的真实 pip 长构建在运行中取消后，其构建子进程退出；双进程同时下载同名、同哈希资源连续六轮得到一份校验正确的成品且没有残留 `.part`。这些实验没有安装真实大型 CUDA Runtime，也不能代表驱动故障或不同版本进程同时写入；遇到这类具体故障再按链路修复，不把用户真实模型当实验对象。
2. **运行状态与诊断：**设备热插拔的失败枚举和过时结果已在隔离测试中覆盖；Peer/Audio/AI Job 的状态与关联时间线使用有界白名单数据。下一步需用真实 USB 设备、房间和录音做切换与降级恢复核对；不能用模拟事件宣称真实设备已经验收。诊断继续不记录聊天、转录正文或凭据。
3. **长期磁盘占用：**程序日志、ASR 临时 WAV、安装资源和大型 SDK 已做用途与体积审计；FFmpeg“无法读取”、录音元数据或 Marker 异常不会触发自动删除，自动回收会重新核对保护状态。隔离目录中 1200 条录音首轮/次轮列表读取约 76/61 毫秒，重复读取 20 次后元数据大小和修改时间不变，没有临时文件残留；这证明该批量夹具和重复读取路径，不等于真实使用数周的增长结论。长时间真实使用和旧版升级后的更新缓存生命周期留待对应设备验收。真实模型 `.part`、录音和待安装包继续保留；用户尚未决定删哪些模型，不能仅凭日期清理。
4. **包体积变更复核：**正式发布获得明确授权后，对那次真实产物重新出报告并校验预算、目标平台资源、安装行为和下载更新路径。2026-09-28 的独立候选包数字只能用作当时快照，不能代表后续代码的精确体积。

上述条目有明确触发条件，不代表每个版本都要重新做全库扫描。新出现可复现的代码缺陷时，先完成最小改动与定向验证，再依 [版本开发与验证手册](development-playbook.md) 决定是否跑 smoke、五人自动化或普通构建；不为了凑架构指标做机械重写。

## 必须由真实环境补齐的验收

- 已安装旧版客户端的“发现更新 → 下载完成 → 用户点击安装并重启”；不能用安装包校验代替。不要为测试覆盖真实用户资料。
- 手机麦克风的手机波形、电脑输入、房间发布、朋友实际听到四阶段逐一确认；自动化侧链和本机输入不代表远端听感。
- 五台真实设备的后加入者音频、房间隔离、Relay/TURN 恢复、屏幕分享、录音、设备热切换和长时间运行；20 条自动化音频路径仅证明模拟条件。
- 当前本地候选程序的登录、快捷键和更新交互；静态打包检查不能证明实际安装及使用行为。
- 2026-09-30 的本地修复还需在开发版窗口确认：可选更新浮窗周围没有浅色遮罩、关闭更新后发布说明可出现、诊断两项按钮展示进行中与完成/失败反馈，以及开启 Windows 精确定位时才出现系统权限请求。代码检查与模拟测试不等于该界面和权限实测。

实机验收需要设备和用户操作时，明确列为待实测并给出步骤。未取得结果前不写“通过”，也不让自动化结论替代实机结论。
