# 切换房间弹窗加载整理

## 原因与修复

3.4.1 安装后的截图显示：弹窗每次挂载都会清空房间数据，等待本地历史和服务端“我的房间”一起返回。加载阶段同时展示大占位区、列表标签和第二条读取提示；只有一个房间时这些内容又被移除，自动高度改变导致居中的窗口跳动。

- 从当前已连接的房间立即填充入口；同账号、同服务器的目录保留一份有界的内存快照，重复打开直接展示。
- 本地历史与服务端目录独立读取，后台刷新不清空当前内容。服务端失败仍保留可见房间并给出错误反馈。
- 请求沿用 generation 防护，账号或服务器改变、组件卸载后丢弃旧结果。缓存按账号与服务器精确隔离，加入仍重新查询永久 RoomID 和容量。
- 弹窗保持 `min(420px, 85dvh)` 高度，标题与关闭按钮固定，主体内部滚动；加载时不再重复显示列表占位。
- 不增加持久化写入，不修改实时媒体、房间切换协议或正式版本号。

## 本地验证

- 全仓库 `corepack pnpm typecheck` 通过。
- 三个变更的 TypeScript 组件/Hook 的 ESLint 检查通过。
- 现有 `room-navigation`、`private-rooms-client`、`architecture-guard` 共 15 项通过；架构预算棘轮通过，既有文件预算未放宽。
- 隔离界面检查使用内存房间和临时 Electron profile，不接触真实凭据、房间历史、音频或服务器。使用现有 3.4.1 编译样式和新增弹窗样式；截图记录位于被忽略的 `test-artifacts/room-switch-review.png`。初期工具的模块加载/截图等待曾超时；改为 Renderer 内采样并直接输出结果后，完整检查通过，记录为 `test-artifacts/room-switch-review.json`。
- 本地历史延迟 500ms、服务端延迟 1000ms 时，首次展示、读取完成、关闭后重新打开的矩形完全一致：448×420 CSS px，位置也一致；三个阶段均没有读取占位。
- 账号切换后旧请求不覆盖新账号，后台请求失败保留当前房间；冷入口在本地历史返回后就可显示，不等待服务端。五种隔离场景全部通过。
- 缩小原生窗口后，实际内容视口为 357 CSS px 高，弹窗为约 303.73px，保持 85dvh 限制，超出内容可在内部滚动。

这是 3.4.1 发布后的本地修复，尚未进入新的安装包。真实已安装客户端需包含本次修改的后续更新后，再确认连续打开和网络较慢时的实际体验。
