# 录音整理与房间上传：2026-10-02

## 用户流程

- 录音库保留三个并列操作：开始转录、整理内容、上传到房间。未转录时整理不可用，未整理完成时上传置灰；上传后显示“已上传到房间”。
- 转录生成文字稿；整理沿用已有的朋友聊天摘要、话题、精彩片段、趣事和参与者要求。云端与自定义 API 同样覆盖完整文字稿、分块整理再合并，不再只处理截断后的单次输入。
- 上传只发送整理摘要及摘要元数据，不发送音频、本地文件路径或完整文字稿。使用云端或自定义 API 整理时，文字稿仍会发送给所选服务，面板已有说明。
- AI 设置顺序为当前使用概览、转录设置、整理与问答、模型。原有两个文本服务选项合并为“整理与问答模型”，默认房间云端，可选自定义 API。
- “自动整理”和“整理后自动上传”在新配置或缺少字段的旧配置中默认关闭；已有明确的自动整理选择保留。自动上传独立控制，整理完成时再次核对开关；需要保持录音对应房间连接。失败保留本地结果，可手动重试。

## 房间及持久化边界

- Main 从录音目录和本地目录索引核对文件身份、永久 RoomID 和录音日期；Renderer 不能通过处理参数重新指定录音所属房间或日期。
- 上传前必须连接录音原房间；服务器用已认证会话再次核对房间。频道号不能用于上传路由，未知所属房间的旧录音不允许上传。
- 房间问答的本地录音检索限制为当前已加入的房间，其他房间的记录不会进入问答输入。
- 日期按原始录音时间换算为上海日期，不按稍后处理时间归档；旧 AI 记录没有原始日期时兼容其原创建时间。服务沿用最近 14 天的每日总结保留窗口。
- 同一录音的自动和手动上传合并为一个请求；已上传结果不重复发送。重新转录或重新整理会清除旧上传标记。
- 上传回执核对房间和日期，再按整理时间进行原子提交；迟到回执不能覆盖新的整理结果、录音名称或其他已保存元数据。
- 服务器完成写盘才确认成功。等待写盘使用独立 flushWrites，保持房间、游戏、成员和分享的活动计时继续运行。

## 每日总结

当天上传的摘要归入录音所属房间的对应日期，次日的每日点评可以参考这些摘要。上传使旧点评缓存失效；生成期间又上传新摘要时，旧版本生成结果不会覆盖新数据。没有事件片段时，房间报告也可展示最近上传摘要的入口内容。
