## 资源边界

两次全程记录的 GPU 峰值最大值（MiB）：Qwen1.7 7785、Qwen0.6 4871、
FireRed3847、Paraformer3160、Dolphin5273、ARK5956、Fun3393、GLM5665、
MOSS Q8 2617、原MOSS3482、Cohere5886。
这是采样得到的设备级显存值，可能包含桌面/其他进程，不是模型独占分配量。
尤其 Qwen1.7 的 7785 MiB 已提示 8GB 卡余量很小；本轮无 OOM 不等于边玩游戏边跑也安全。

RAM 指标是被监测进程的峰值，不代表全系统或完整进程树；不能把 MOSS Q8 的
约 867 MiB 直接与 Python 模型比较并宣称总内存最省。FireRed 被监测峰值约
9800 MiB，Qwen0.6 约2815 MiB，Qwen1.7 约5046 MiB。缺全进程树统计，
本轮不制作综合内存排名。

## 失败归因与实际修复

- 原 MOSS：已证实解析空正文回退原始控制标记是适配缺陷。已修复、2 项回归通过，
  真实原块输出 text=空 / segments=空 / rawText 保留。它仍属失败，不伪装成功。
- MOSS Q8：原片段在官方 CPU 和 Vulkan 调用均出现标记循环/截断。
  切换 CPU 不能修复；未证实究竟是权重还是上游运行时问题。
- Cohere：精确定位到独立音轨的失败原块，官方独立调用仍重复，见
  COHERE_ORIGINAL_UNIT.md。可排除上号队列/适配器是该样本的必要成因，
  不能排除依赖/runtime 或输入内容敏感性。
- ARK、Fun、GLM 的剩余少量异常仍需原块人工听审和独立复现；检测命中不能
  自动等同识别差。它们不因分段数或已知用户身份下的 diarization 能力加减分。

修复发生在上述 88 项之后，源哈希已改变。没有覆盖历史结果或把修复前成绩
标记成修复后验证。桌面三张历史截图仅提供质量候选线索，未混入本轮数值。

## 现在可以决定什么

建议日常候选先保留 Qwen 双版本、FireRed、Paraformer；Dolphin 作专项对照。
MOSS 双版本和 Cohere 可以在未来 UI 中标为实验候选，但本轮未修改列表、
未卸载模型、未改变默认配置。**目前没有充分证据建议永久删除任何模型。**

识别准确率排名仍缺人工真值；本轮不伪造 CER 或百分制总分。真正的最终质量
排序需要同片段盲评（中文、游戏词、数字、英文、重叠说话、长静音），并把
适配失败单独列出。客户端开始/暂停/继续/切换录音/结果显示的真实后端联动
也仍需独立验证；已有后台全程结果不能替代。
