# 房间 AI 记忆（2026-10-03）

## 使用方式

设置 → 账号 → 我的房间 → 管理，新增“房间记忆”。房主可以填写成员称呼、人物关系、长期偏好和约定，点击“保存记忆”提交。手动内容最多 4,000 字，优先于自动条目。

新房间记忆默认开启自动提取。服务器从**已上传的录音整理摘要**提取有原文依据的长期事实；不会自动上传本地录音或未分享的转录，也不根据昵称猜测身份。自动条目可编辑、删除，附摘要日期及原始依据。关闭自动记忆后保留已有内容供 AI 参考，不再追加。

AI 问答、录音整理、每日总结生成前读取本房间的有界记忆，作为参考资料，只使用相关事实。房间云端与自定义 API 都已接入；自定义模型按用户选定的 API 接收参考内容。已有日报不会因编辑记忆自动重写。

## 权限与数据

- 每个永久 RoomID 对应独立记忆。房主可读写；当前已连接且未被封禁的成员可读；其他账号不能通过知道频道号或 RoomID 读取。成员退出及房间删除后复核访问权限。
- URL 决定房间身份，忽略请求正文伪造的 RoomID。补上从旧频道读取私人房间日报的限制；旧频道之间的原有浏览保持兼容。
- Main 通过显式 `roomMemory.get/save` 能力持有 token，Renderer 不接触凭据。账号或服务器变化后的迟到回执被拒绝，界面按服务器、账号与 RoomID 重建。
- 独立格式 `version: 1`，路径为 `ROOM_DIRECTORY_FILE` 的实际文件路径加 `.memory.json`；沿用单进程写入约束及同一持久目录的权限。没有改写原房间目录、聊天、录音或转录数据。
- 存储复用 `VersionedJsonStore` 的串行事务、临时文件独占创建、同步及原子替换。修改前以房间 revision 检查冲突；提交失败不更新读缓存；返回值是独立副本。未知格式、损坏或超大文件保留并报告错误。
- 整个文件最多 16 MiB / 10,000 个房间，读取前检查体积，写入前检查体积与 revision。每房间最多 32 条事实，每条 240 字，原始依据最多 300 字；来源指纹与删除记录分别保留最近 256 项。达到容量时保留已有内容，不淘汰现有条目。
- 查询只复制本房间的缓存，不为每次 AI 问答复制全部房间数据；写事务仍是有界的完整 JSON 快照。未来多实例或更大规模需采用共享事务存储，不能同时让多个进程写同一文件。

## 自动提取与界面边界

摘要持久保存并 ACK 后才触发后台提取，每次最多 8 条；最多两个并发、32 个待处理摘要，同一房间串行执行。提取器只读取新摘要，不拿旧记忆当证据；输出必须为 JSON，原始依据必须出现在摘要中。

模型未配置、无明确事实、超时或错误时不写假记忆。自动任务有 10 秒期限，关闭服务时取消并等待收尾；队列不是持久任务数据库，重启不补录未处理任务，需要时可重新上传摘要重试。没有自动扫描历史本地录音，没有对线上模型提取质量作已实测承诺。

手动修改或关闭开关会使迟到提取结果失效。刷新采用三方合并：保留本地编辑和删除，接纳未改动字段的远端更新及新条目；远端已删除但本地改过的事实移入手动文本，超出上限则保留草稿并报冲突。双击保存只提交一次。读取时预留完整编辑区与状态行，避免加载结束后弹窗突然缩小。

旧服务器没有记忆接口时，客户端核对原房间仍存在后提示服务器需要升级；自定义 API 保持原有无房间记忆的行为。真实房间已删除、权限错误、格式错误和存储损坏不会被伪装成空记忆。
